# 实验1 跑马灯实验

> 让开发板上的红、蓝两颗 LED 交替闪烁，是嵌入式学习的"Hello World"。难度：入门

## 1. 例程简介

本例程控制 DNK230D 开发板上板载的双色 LED（红色和蓝色）轮流点亮、轮流熄灭，形成"跑马灯"效果。通过它你将学会 CanMV MicroPython 中最基础的两件事：**FPIOA 引脚功能映射**和 **GPIO 输出高低电平**。难度为**入门**，是所有后续实验（按键、蜂鸣器、PWM 等）的地基，预期用途是验证开发板、固件和 IDE 环境是否正常工作。

## 2. 硬件连接与原理

本实验**不需要任何外接接线**，只使用板载资源：

| 外设 | 引脚 | 代码中的对象 |
| --- | --- | --- |
| 蓝色 LED | GPIO59（物理 Pin59） | `ledb` |
| 红色 LED | GPIO61（物理 Pin61） | `ledr` |

### 硬件原理（通俗版）

LED（发光二极管）具有单向导电性：电流从正极流向负极时才会发光。开发板上的 LED 一端接电源（或地），另一端通过限流电阻接到 K230D 芯片的 GPIO 引脚上。芯片引脚输出**高电平**（约 3.3V）或**低电平**（0V）时，LED 两端的电压差发生变化，灯就会亮或灭。

本例程中的写法是：

```python
ledb.value(1)   # 输出高电平
ledb.value(0)   # 输出低电平
```

代码通过让一颗灯输出高的同时另一颗输出低，再延时 200 毫秒后交换，就形成了交替闪烁的效果。

### 新手风险提醒

> [!WARNING]
> - 本实验无需插拔任何杜邦线，但请**先接好 USB 供电线再运行程序**，运行中不要拔插外设。
> - 开发板扩展 GPIO 是 **3.3V 电平**，如果以后你外接其他模块，切勿接入 5V 信号，否则可能烧毁芯片。
> - LED 已经串联了限流电阻，直接点亮是安全的；不要自己用导线短接 LED 引脚和电源。

## 3. 相关前置知识

- **GPIO（通用输入输出）**：芯片上可以被程序控制的引脚，可以配置为"输出"（往外给电平）或"输入"（读外面来的电平）。本实验把两个引脚配置为输出。
- **高电平 / 低电平**：数字电路里两种状态。高电平约等于 3.3V，代表逻辑"1"；低电平约等于 0V，代表逻辑"0"。`pin.value(1)` 就是输出高电平。
- **FPIOA（可编程 IO 阵列）**：K230D 芯片的一个特色设计——芯片的物理引脚（Pin）默认不绑定任何功能，需要先用软件把某个 Pin "映射"成 GPIO、PWM、UART 等功能，然后才能使用。这就是代码里 `fpioa.set_function()` 的作用。
- **`time.sleep_ms()`**：毫秒级延时函数，让程序"停下来等一会儿"，人眼才能看到灯的闪烁，否则会快到看不清。

## 4. 软件代码逻辑说明

整体流程：**导入模块 → FPIOA 映射 → 构造 GPIO 对象 → 主循环交替输出**。

### 第 1 步：导入模块

```python
from machine import Pin
from machine import FPIOA
import time
```

`machine` 是 MicroPython 官方的硬件访问模块，`Pin` 用来操作 GPIO，`FPIOA` 用来做引脚功能映射，`time` 提供延时。

### 第 2 步：FPIOA 引脚功能映射

```python
fpioa = FPIOA()
fpioa.set_function(59, FPIOA.GPIO59)
fpioa.set_function(61, FPIOA.GPIO61)
```

`set_function(物理引脚号, 目标功能)` 把 Pin59 配置成 GPIO59、Pin61 配置成 GPIO61。**这一步在 K230D 上是必须的**，忘了映射引脚就不会有输出。

### 第 3 步：构造 GPIO 输出对象

```python
ledr = Pin(61, Pin.OUT, pull=Pin.PULL_NONE, drive=7)
ledb = Pin(59, Pin.OUT, pull=Pin.PULL_NONE, drive=7)
```

- `61` / `59`：GPIO 编号（映射后与引脚号一致）。
- `Pin.OUT`：配置为输出模式。
- `pull=Pin.PULL_NONE`：不启用内部上拉/下拉电阻（输出模式不需要）。
- `drive=7`：引脚驱动能力设为 7（数值越大带载能力越强，0~7 可选）。

### 第 4 步：主循环——交替点亮

```python
while True:
    ledb.value(1)
    ledr.value(0)
    time.sleep_ms(200)
    ledb.value(0)
    ledr.value(1)
    time.sleep_ms(200)
```

`while True` 是死循环：先让蓝灯输出高、红灯输出低，保持 200ms；再反过来，保持 200ms。如此往复，两颗灯交替闪烁。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `FPIOA().set_function(pin, func)` | 把物理引脚映射为指定功能 |
| `Pin(id, Pin.OUT, ...)` | 创建输出模式的 GPIO 对象 |
| `pin.value(0/1)` | 输出低/高电平（等价的还有 `pin.on()`、`pin.off()`、`pin.high()`、`pin.low()`，代码注释中已列出） |
| `time.sleep_ms(n)` | 延时 n 毫秒 |

### 可调参数

- `time.sleep_ms(200)`：改大闪烁变慢，改小变快；改到 10ms 以下人眼会看到两灯"同时亮"（视觉暂留）。
- `drive=7`：驱动能力，一般不需要改。

## 5. 运行效果

- **成功现象**：开发板上蓝色 LED 和红色 LED 以约 2.5 次/秒的频率交替闪烁（一亮一灭轮流）；CanMV IDE 串口终端无报错。
- **失败现象排查**：
  1. 灯完全不亮 → 检查 IDE 是否已连接开发板、程序是否真正在运行（IDE 左下角状态）。
  2. 报错 `AttributeError` / 找不到 `FPIOA` → 固件不是 CanMV K230D 专用固件，见第 6 节。
  3. 两灯同时亮或同时灭 → 检查是否修改过代码中的 GPIO 编号（59、61）。

## 8. 常见问题

**Q1：为什么代码里要先 `fpioa.set_function()`，直接用 `Pin(61)` 不行吗？**
A：不行。K230D 的物理引脚默认不分配功能，`set_function` 就是告诉芯片"Pin61 请当作 GPIO61 用"。跳过这一步，后面创建的 `Pin` 对象操作的是一个没有连通的引脚，LED 不会有任何反应。这是 K230D 与 STM32 等单片机的最大区别之一。

**Q2：LED 闪烁太快/太慢怎么办？**
A：闪烁速度由 `time.sleep_ms(200)` 决定，单位是毫秒。想要 1 秒闪一次就改成 `time.sleep_ms(1000)`（注意一次完整交替有两次延时，共 2 个周期参数）。

**Q3：程序运行后 IDE 点击"停止"没反应，或者板子像卡死了一样？**
A：`while True` 死循环会一直占用解释器。若 IDE 无法正常停止，可按开发板 **RESET 复位按键**，或重新上电；这不会损坏程序。

**Q4：`drive=7` 是什么意思？可以改成 0 吗？**
A：`drive` 设置引脚的驱动电流能力（0~7）。7 是较强的驱动，点亮板载 LED 绰绰有余。改小后 LED 可能变暗甚至点不亮，初学者保持默认即可。

**Q5：为什么注释里写"设置输出为高"后又立刻"设置输出为低"？**
A：文件开头那两行 `ledb.value(1)`、`ledb.value(0)` 只是演示 `value()` 用法的示例代码，执行非常快，肉眼看不到闪烁；真正产生跑马灯效果的是下面 `while True` 主循环。
