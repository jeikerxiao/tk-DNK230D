# 实验4 WDT实验

> 认识看门狗：3 秒不"喂狗"系统就自动复位，喂满 5 次后故意不喂，亲眼看门狗如何救场。难度：初级

## 1. 例程简介

本例程演示 **WDT（Watchdog Timer，看门狗定时器）** 的工作原理：程序启动后创建一个超时时间为 3 秒的看门狗，每按一次 KEY0 就"喂狗"一次（重置看门狗计时）；连续喂 5 次后程序**故意不再喂狗**，3 秒后看门狗超时，系统自动复位重启。你将学会看门狗的创建、喂狗方法，理解它为什么是嵌入式系统防死机的"保险丝"。难度为**初级**。

## 2. 硬件连接与原理

使用板载资源，无需外接：

| 外设 | 引脚 | 代码中的对象 |
| --- | --- | --- |
| KEY0 按键 | GPIO34（内部上拉，按下读 0） | `key0` |
| 看门狗 | 芯片内部 WDT1（无需引脚） | `wdt1` |

### 硬件原理（通俗版）

**看门狗**是芯片内部的一个倒计时定时器。启动后它开始倒数（本例 3 秒），如果倒数到 0 之前程序调用了 `feed()`（喂狗），倒计时就重新从 3 秒开始；如果程序跑飞、死机或陷入死循环，**没人喂狗**，倒计时归零后看门狗会强制**复位整个系统**，让程序重新启动，从而摆脱卡死状态。

打个比方：看门狗就像要求你"每 3 秒必须打一次卡"的监工，忘了打卡它就拉闸重启机器。正常的程序会在主循环里定期打卡；出 bug 卡住时，"重启大法"自动生效。

本实验的 KEY0 就是"手动打卡按钮"：按一下喂一次狗。喂满 5 次后程序退出喂狗逻辑，你只需静静等 3 秒，就能观察到系统自动重启（终端重新打印 `system start-up`）。

### 新手风险提醒

> [!WARNING]
> - 实验末尾系统会**自动复位**，这是正常设计，不是板子坏了。
> - 复位瞬间 USB 串口可能短暂断开，IDE 终端偶尔显示连接异常，重新连接即可。
> - 调试其他程序时若创建了看门狗却忘了喂狗，会导致程序"莫名其妙反复重启"，记住先检查 WDT 代码。

## 3. 相关前置知识

- **复位（Reset）**：系统重新从头启动，等同于按复位键或重新上电。程序中的变量全部清零重来。
- **看门狗超时时间（timeout）**：允许"最长多久不喂狗"，本例为 3 秒。
- **喂狗（feed）**：调用 `wdt.feed()` 把倒计时重置回超时时间，表示"程序还活着"。
- **按键消抖**：机械按键按下瞬间电平会抖动几毫秒。代码采用"检测到按下 → 延时 20ms → 再确认一次"的软件消抖法，防止一次按键被算成多次喂狗。
- **GPIO 上拉输入**：`pull=Pin.PULL_UP` 使按键松开时读 1、按下接地读 0（详见[实验3 按键输入实验](../实验3%20按键输入实验/README.md)）。
- **格式化打印**：`print("Feed WDT1 %d times." % (feed_times))` 中的 `%d` 是整数占位符，运行时被变量值替换。

## 4. 软件代码逻辑说明

流程：**FPIOA 映射 → 构造按键 → 创建看门狗 → 循环等待按键喂狗（最多 5 次）→ 不喂狗等待复位**。

### 第 1 步：FPIOA 映射与按键对象

```python
fpioa = FPIOA()
fpioa.set_function(34, FPIOA.GPIO34)
key0 = Pin(34, Pin.IN, pull=Pin.PULL_UP, drive=7)
```

把 Pin34 映射为 GPIO34，构造上拉输入的 KEY0 对象。

### 第 2 步：创建看门狗

```python
wdt1 = WDT(1, 3)
print("system start-up")
```

`WDT(1, 3)`：第一个参数是**看门狗编号 1**（即 WDT1），第二个参数是**超时时间 3 秒**。创建即开始倒计时。紧接着打印启动横幅——每次系统复位后都会重新打印它，这正是我们判断"发生了复位"的标志。

### 第 3 步：喂狗主循环

```python
feed_times = 0

while feed_times < 5:
    if key0.value() == 0:          # 检测到 KEY0 按下
        time.sleep_ms(20)          # 延时 20ms 消抖
        if key0.value() == 0:      # 再次确认仍按下
            wdt1.feed()            # 对WDT喂狗
            feed_times += 1
            print("Feed WDT1 %d times." % (feed_times))
            while key0.value() == 0:   # 等待松手，防止一次长按喂多次
                pass
    time.sleep_ms(10)
```

逐层拆解：

1. `while feed_times < 5`：只允许喂 5 次，喂满后循环退出。
2. 两级 `if key0.value() == 0` + 中间 `sleep_ms(20)`：经典软件消抖。
3. `wdt1.feed()`：喂狗，3 秒倒计时重新开始。
4. `feed_times += 1` 并打印喂狗次数。
5. `while key0.value() == 0: pass`：原地等待松手，避免一次长按在几十毫秒内被重复计数。
6. 循环末尾 `time.sleep_ms(10)`：降低轮询频率、减轻 CPU 占用。

> [!NOTE]
> 注意整个喂狗过程必须**在 3 秒内完成一次按键**，否则倒计时归零、系统提前复位、计数从头开始。所以按 KEY0 的节奏不能太慢！

### 第 4 步：循环退出后

脚本自然结束，没有任何代码再调用 `wdt1.feed()`。看门狗 3 秒倒计时归零 → **硬件复位系统** → 程序重新从头运行，再次打印 `system start-up`。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `WDT(id, timeout)` | 创建编号为 id、超时 timeout 秒的看门狗，创建即启动 |
| `wdt.feed()` | 喂狗，重置倒计时 |
| `key.value()` | 读取按键电平 |

### 可调参数

- `WDT(1, 3)` 的超时时间 `3`：改大（如 10）喂狗节奏可以更从容；改小（如 1）则必须快速连按。
- `while feed_times < 5` 的次数 `5`：决定喂多少次后"放手不管"等复位。
- 消抖延时 `20`（毫秒）：过小消抖不彻底，过大影响手感。

## 5. 运行效果

- **成功现象**：
  1. 运行后 IDE 终端打印 `system start-up`；
  2. 3 秒内按一次 KEY0，打印 `Feed WDT1 1 times.`，依次类推；
  3. 喂到 `Feed WDT1 5 times.` 后不再喂狗；
  4. 约 3 秒后系统自动复位，终端**再次出现 `system start-up`**——证明看门狗复位生效。
- **失败现象排查**：
  1. 还没喂满 5 次就重启了 → 两次按键间隔超过 3 秒，加快按键节奏，或把超时时间改大。
  2. 按键没打印 → 检查 GPIO34 映射与消抖逻辑；确认按的是 KEY0。
  3. 一直不复位 → 确认代码没有多余的 `feed()` 调用；确认 `WDT(1, 3)` 成功创建（无异常打印）。

## 7. 拓展思考

1. **体验"程序卡死被救"**：把 `wdt1.feed()` 那一行注释掉再运行，观察程序启动后 3 秒即自动复位、无限循环重启——这就是看门狗处理死机的真实场景。
2. **LED 心跳指示**：结合[实验1 跑马灯实验](../实验1%20跑马灯实验/README.md)，让 LED 每闪一次就喂一次狗；把 LED 循环改成死循环卡住（去掉喂狗），观察灯灭 3 秒后系统重启。
3. **调整超时参数**：把超时改为 1 秒、10 秒分别实验，记录"最慢按键节奏"，理解超时时间与任务周期的匹配关系（工程上一般取最长任务周期的 2~3 倍）。

## 8. 常见问题

**Q1：`WDT(1, 3)` 里的 `1` 是什么？可以用别的编号吗？**
A：`1` 是看门狗外设的编号（WDT1）。芯片内部有多路看门狗资源，不同固件版本可用的编号可能不同，本例程按官方 CanMV K230D 固件使用编号 1；若实例化时报错，请查阅所用固件版本的文档确认支持的 WDT 编号。

**Q2：为什么喂满 5 次后系统重启了？这是 bug 吗？**
A：不是 bug，正是实验目的。喂满 5 次后 `while` 循环退出，再没有代码调用 `feed()`，3 秒后看门狗超时强制复位。终端重新出现 `system start-up` 就是复位的证据。

**Q3：看门狗复位和断电重启有什么区别？**
A：看门狗复位是芯片内部的复位信号，不断电、速度快，RAM 之外的外设全部回到初始状态；断电重启是彻底掉电。对程序而言两者效果类似：`main.py` 从头执行。

**Q4：实际产品中看门狗应该怎么用？**
A：在主循环的固定位置调用 `feed()`，并把超时时间设置为明显大于"主循环正常跑一圈的最长时间"。这样程序正常运行时总能按时喂狗；一旦死机或死循环，看门狗自动复位恢复。

**Q5：为什么按一次 KEY0 只喂一次狗？我一直按住会怎样？**
A：代码中 `while key0.value() == 0: pass` 会一直等到你松手才继续循环，所以长按也只计一次。如果不写这句，长按时循环会在几毫秒内喂狗几十次，计数瞬间爆掉。
