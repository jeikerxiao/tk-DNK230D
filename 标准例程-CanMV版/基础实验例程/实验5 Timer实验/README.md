# 实验5 Timer实验

> 用定时器每 1 秒自动翻转红色 LED，按一下 KEY0 停止定时器，理解"回调"这种编程思想。难度：初级

## 1. 例程简介

本例程创建一个**周期为 1000 毫秒的软件定时器**，让它每隔 1 秒自动执行一次回调函数，把红色 LED 的状态翻转一次（亮→灭→亮……），完全不占用主循环；按下 KEY0 则调用 `deinit()` 释放定时器，LED 停止闪烁。你将学到 **Timer 定时器、回调函数、中断上下文中的全局变量** 等概念。难度为**初级**，定时器是实现"多任务节奏控制"的基础工具。

## 2. 硬件连接与原理

使用板载资源，无需外接：

| 外设 | 引脚 | 代码中的对象 |
| --- | --- | --- |
| KEY0 按键 | GPIO34（内部上拉，按下读 0） | `key0` |
| 红色 LED | GPIO61 | `ledr` |
| 定时器 | 芯片内部资源（软件定时器编号 -1） | `tim` |

### 硬件原理（通俗版）

**定时器（Timer）** 是系统内部的"闹钟"：你告诉它"每 1000 毫秒叫我一次"，它就由硬件/系统底层计时，时间一到自动执行你事先登记的函数（称为**回调函数**），主程序完全不用干等。

对比[实验1 跑马灯实验](../实验1%20跑马灯实验/README.md)里用 `time.sleep_ms()` 阻塞式闪灯的做法，定时器方式的最大好处是：**主循环仍然自由**——本例的主循环还在同时轮询 KEY0，闪灯和按键检测互不干扰。这就是"非阻塞"编程思想。

LED 部分与实验 1 相同：GPIO61 输出 0 点亮、输出 1 熄灭。回调里用 `count % 2`（计数值除以 2 的余数，只能是 0 或 1）来实现"每次翻转"。

### 新手风险提醒

> [!WARNING]
> - 回调函数在**中断上下文**中执行（可以理解为"插队"执行），里面不要写耗时操作（如大量打印、文件读写、长延时），否则可能导致系统不稳定。
> - 定时器一旦启动就持续触发，实验结束记得按 KEY0 释放或在 IDE 停止程序。
> - 无需接线，但插拔外设前请断开 USB 供电。

## 3. 相关前置知识

- **回调函数（callback）**：你把一个函数"登记"给某个机制，条件满足时机制自动调用它。就像订外卖：你留了电话（回调），餐到了骑手自动打给你，而不用一直守在门口。
- **周期模式（PERIODIC）vs 单次模式（ONE_SHOT）**：周期模式每次超时后自动重新开始计时、反复触发；单次模式只触发一次。本例用周期模式。
- **软件定时器**：`Timer(-1)` 表示由系统软件层管理的定时器，负数编号区别于芯片的硬件定时器通道，数量有限、精度略低，但使用灵活。
- **`global` 关键字**：函数内部要给**函数外定义的变量**赋值，必须先用 `global` 声明，否则 Python 会认为你在函数里新建了一个局部变量。
- **取余运算 `%`**：`count % 2` 得到 count 除以 2 的余数，奇数为 1、偶数为 0，天然适合做"翻转"逻辑。
- **按键消抖**：延时 20ms 二次确认，防止一次按键触发多次（同[实验4 WDT实验](../实验4%20WDT实验/README.md)）。

## 4. 软件代码逻辑说明

流程：**FPIOA 映射 → 构造按键和 LED → 定义回调 → 创建并启动定时器 → 主循环等待 KEY0 停止定时器**。

### 第 1 步：FPIOA 映射与 GPIO 对象

```python
fpioa = FPIOA()
fpioa.set_function(34, FPIOA.GPIO34)
fpioa.set_function(61, FPIOA.GPIO61)

key0 = Pin(34, Pin.IN, pull=Pin.PULL_UP, drive=7)
ledr = Pin(61, Pin.OUT, pull=Pin.PULL_NONE, drive=7)
count = 0
```

KEY0 上拉输入（按下读 0），红色 LED 输出，`count` 是全局计数器。

### 第 2 步：定义定时器回调函数

```python
def timer_timeout_cb(timer):
    global count
    count = count + 1
    ledr.value(count % 2)
```

定时器每次超时都会自动调用这个函数：

- 参数 `timer` 是触发该回调的定时器对象（本例没用到它）。
- `global count`：声明要修改全局变量 `count`。
- 每来一次计数加 1，`count % 2` 在 0 和 1 之间交替，于是 `ledr.value()` 交替输出低（亮）和高（灭）。

### 第 3 步：创建并初始化定时器

```python
tim = Timer(-1)
tim.init(period = 1000, mode = Timer.PERIODIC, callback = timer_timeout_cb)
```

- `Timer(-1)`：申请一个**软件定时器**（编号 -1 表示由系统自动分配的软件定时器）。
- `init()` 三个参数：
  - `period=1000`：超时周期 1000 毫秒（1 秒）；
  - `mode=Timer.PERIODIC`：周期模式，反复触发；
  - `callback=timer_timeout_cb`：登记回调函数（注意只传函数名，不加括号）。

### 第 4 步：主循环——按 KEY0 停止定时器

```python
while True:
    if key0.value() == 0:
        time.sleep_ms(20)          # 消抖
        if key0.value() == 0:
            tim.deinit()           # 释放Timer资源
            while key0.value() == 0:
                pass               # 等待松手
    time.sleep_ms(10)
```

主循环平时只做轻量轮询；检测到 KEY0 按下（消抖确认后）调用 `tim.deinit()` **停止并释放定时器**，此后回调不再被调用，LED 停在当前状态。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `Timer(-1)` | 创建软件定时器对象 |
| `tim.init(period, mode, callback)` | 启动定时器：周期(毫秒)、模式、回调 |
| `Timer.PERIODIC` | 周期模式常量（另有 `Timer.ONE_SHOT` 单次模式） |
| `tim.deinit()` | 停止并释放定时器 |

### 可调参数

- `period=1000`：闪烁周期。改成 200 灯闪得快，改成 3000 每 3 秒翻转一次。注意"翻转周期"是 period，"一次完整亮灭"需要 2 个 period。
- `mode`：换成 `Timer.ONE_SHOT`，回调只执行一次，LED 翻转一下就不再变化。
- 回调里 `count % 2`：改成 `count % 3` 会发现灯在"亮、灭、灭"间循环（value 为 0、1、2，但 2 仍输出高），体会取余与电平的关系。

## 5. 运行效果

- **成功现象**：
  1. 程序运行后，红色 LED 每 1 秒翻转一次（亮 1 秒、灭 1 秒循环）；
  2. 期间按下 KEY0，LED 立即停止翻转，保持当前状态；
  3. 再按 KEY0 不会有任何反应（定时器已释放，只能重新运行程序恢复）。
- **失败现象排查**：
  1. 灯不闪 → 检查 GPIO61 映射；确认 `init()` 成功执行没有抛异常。
  2. 闪得太快/太慢 → 核对 `period` 数值（单位是毫秒）。
  3. 按 KEY0 不停 → 确认按的是 KEY0（GPIO34），消抖代码是否完整。
  4. 程序卡死或异常 → 检查是否在回调里加了耗时操作（打印、延时等），回调必须精简。

## 8. 常见问题

**Q1：`Timer(-1)` 的 `-1` 是什么意思？**
A：负数编号表示申请**软件定时器**（由固件的软件层模拟，不占用硬件定时器通道）；非负编号则对应芯片的硬件定时器。软件定时器数量多、使用灵活，适合秒级/百毫秒级的任务，本实验用 `-1` 让系统自动分配一个。

**Q2：为什么回调函数里必须写 `global count`？**
A：Python 规定：函数内部对变量**赋值**时，默认会创建同名的局部变量。`count = count + 1` 想修改的是函数外面定义的 `count`，所以必须先 `global count` 声明。不写会报 `NameError` 或计数永远是局部值。

**Q3：回调里可以 `print()` 吗？**
A：不建议。回调在中断上下文中执行，`print` 这类耗时的 IO 操作可能阻塞系统、导致其他中断丢失甚至死机。需要调试时可以在回调里置一个标志变量，由主循环去打印。

**Q4：按了 KEY0 之后 LED 停在"亮"的状态，正常吗？**
A：正常。`deinit()` 只是停止后续回调，不会改变 LED 当前电平。想让灯灭掉，可以在 `tim.deinit()` 后加一句 `ledr.value(1)`。

**Q5：`period=1000` 时，为什么感觉灯是"1 秒亮 1 秒灭"而不是"1 秒闪一次"？**
A：因为回调每 1000ms 才**翻转**一次电平：第 1 秒变亮，第 2 秒变灭，第 3 秒又变亮……一个完整的亮灭周期是 2 秒。想要"每秒完整闪一次"，应把 `period` 改为 500。
