# 实验3 按键输入实验

> 按下 KEY0/KEY1 分别点亮红灯/蓝灯，按住 KEY2 蜂鸣器鸣叫，学会读取外部输入。难度：入门

## 1. 例程简介

本例程读取开发板上 3 个板载按键 KEY0、KEY1、KEY2 的状态：按住 KEY0 点亮红色 LED，按住 KEY1 点亮蓝色 LED，按住 KEY2 让蜂鸣器鸣叫，松开即恢复。你将学会 **GPIO 输入模式、上拉/下拉电阻、按键电平判断**，并复习 GPIO 输出和 PWM。难度为**入门**，是所有"人机交互"类项目（菜单、控制、触发拍照等）的基础。

## 2. 硬件连接与原理

本实验全部使用板载资源，**无需外接接线**：

| 外设 | 引脚 | 代码中的对象 | 按下时的电平 |
| --- | --- | --- | --- |
| KEY0 按键 | GPIO34（内部上拉） | `key0` | 低（0） |
| KEY1 按键 | GPIO35（内部上拉） | `key1` | 低（0） |
| KEY2 按键 | GPIO0（内部下拉） | `key2` | 高（1） |
| 红色 LED | GPIO61 | `ledr` | 输出 0 点亮 |
| 蓝色 LED | GPIO59 | `ledb` | 输出 0 点亮 |
| 蜂鸣器 | Pin60 → PWM0 | `beep` | `enable(True)` 发声 |

### 硬件原理（通俗版）

按键就是一个"手动开关"：没按下时引脚通过电阻保持在某个固定电平，按下后引脚被接通到相反的电源轨，电平翻转。程序不断读取引脚电平，就知道按键有没有被按下。

本板 KEY0、KEY1 一端接地：平时靠**内部上拉电阻**把引脚拉在高电平（读到 1），按下时引脚直接接地（读到 0），所以判断条件是 `key0.value() == 0`。

KEY2 接法相反（一端接电源，且该引脚还兼作**启动模式选择**），所以代码给它配置了**内部下拉** `pull=Pin.PULL_DOWN`，平时读 0，按下读 1，判断条件是 `key2.value() == 1`。

LED 部分：引脚输出低电平（0）时灯亮、输出高电平（1）时灯灭——这是由板上 LED 的接法决定的，属于"低电平点亮"。

### 新手风险提醒

> [!WARNING]
> - KEY2 兼作**启动模式选择键**（SD NAND / TF 卡启动切换）：只有在**上电/复位瞬间按住**才会影响启动模式，程序运行中按下它只是普通按键，不会重启或切换系统，不必担心。
> - 插拔任何外设前请先断开 USB 供电，避免短路。
> - 不要将扩展引脚接超过 3.3V 的信号。

## 3. 相关前置知识

- **GPIO 输入模式**：引脚作为"读取"用途，`Pin(34, Pin.IN, ...)` 中的 `Pin.IN` 表示输入。调用 `pin.value()` 返回 0 或 1。
- **上拉电阻（PULL_UP）**：一个接在引脚和电源之间的电阻，让引脚"悬空时"默认读到高电平 1。按下接地的按键时变为 0。
- **下拉电阻（PULL_DOWN）**：反过来，让引脚默认读到低电平 0，按键接电源时按下变 1。KEY2 就是这种。
- **轮询（Polling）**：程序在循环里不停地"主动问"引脚状态，而不是等硬件事件通知。本例是典型的轮询写法，简单可靠。
- **PWM 使能控制**：`beep.enable(True/False)` 动态开启/关闭 4KHz 方波输出（原理见[实验2 蜂鸣器实验](../实验2%20蜂鸣器实验/README.md)）。

## 4. 软件代码逻辑说明

流程：**FPIOA 映射 → 构造输入/输出/PWM 对象 → 主循环轮询按键并驱动外设**。

### 第 1 步：FPIOA 功能映射

```python
fpioa = FPIOA()
fpioa.set_function(59, FPIOA.GPIO59)
fpioa.set_function(61, FPIOA.GPIO61)
fpioa.set_function(60, FPIOA.PWM0)
fpioa.set_function(34, FPIOA.GPIO34)
fpioa.set_function(35, FPIOA.GPIO35)
fpioa.set_function(0, FPIOA.GPIO0)
```

6 个引脚分别映射为：两个 LED 的 GPIO、蜂鸣器的 PWM0、三个按键的 GPIO。注意 **KEY2 用的是 Pin0/GPIO0**。

### 第 2 步：构造各外设对象

```python
ledb = Pin(59, Pin.OUT, pull=Pin.PULL_NONE, drive=7)
ledr = Pin(61, Pin.OUT, pull=Pin.PULL_NONE, drive=7)
beep = PWM(0, 4000, duty=50, enable=False)
key0 = Pin(34, Pin.IN, pull=Pin.PULL_UP, drive=7)
key1 = Pin(35, Pin.IN, pull=Pin.PULL_UP, drive=7)
key2 = Pin(0, Pin.IN, pull=Pin.PULL_DOWN, drive=7)
```

- LED：输出模式，不启用上下拉。
- 蜂鸣器：PWM 通道 0、4KHz、占空比 50%，**创建时不使能**（`enable=False`），所以刚运行不响。
- KEY0/KEY1：输入模式 + 内部**上拉**（松开读 1，按下读 0）。
- KEY2：输入模式 + 内部**下拉**（松开读 0，按下读 1）。

### 第 3 步：主循环轮询

```python
while True:
    # 读取按键状态，并做相应的按键解释
    if key0.value() == 0:
        ledr.value(0)
    else:
        ledr.value(1)
    if key1.value() == 0:
        ledb.value(0)
    else:
        ledb.value(1)
    if key2.value() == 1:
        beep.enable(True)
    else:
        beep.enable(False)
```

每圈循环做 3 组判断：

1. KEY0 按下（读 0）→ 红灯输出 0（点亮）；松开 → 输出 1（熄灭）。
2. KEY1 按下 → 蓝灯点亮；松开 → 熄灭。
3. KEY2 按下（读 **1**）→ 使能 PWM，蜂鸣器响；松开 → 关闭 PWM，停止发声。

三个 `if` 相互独立，所以可以**同时**按多个键，多个外设一起响应。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `Pin(id, Pin.IN, pull=...)` | 创建输入模式 GPIO，可带上拉/下拉 |
| `key.value()` | 读取引脚电平，返回 0 或 1 |
| `led.value(0/1)` | 输出电平控制 LED（本板 0=亮，1=灭） |
| `beep.enable(True/False)` | 动态开启/关闭 PWM 波形输出 |

### 可调参数

- 判断电平 `== 0` / `== 1`：必须与按键实际接法和上下拉配置对应，改错会导致"按下不亮、松开常亮"的反逻辑。
- `pull=Pin.PULL_UP/PULL_DOWN`：上拉还是下拉决定了松开时的默认电平。
- 本例没有加延时消抖，因为轮询速度极快、LED/蜂鸣器对几毫秒的抖动不敏感；如果你要拿按键做"计数"，请参考[实验4 WDT实验](../实验4%20WDT实验/README.md)和[实验5 Timer实验](../实验5%20Timer实验/README.md)中的消抖写法。

## 5. 运行效果

- **成功现象**：
  - 按住 KEY0：红色 LED 亮，松开熄灭；
  - 按住 KEY1：蓝色 LED 亮，松开熄灭；
  - 按住 KEY2：蜂鸣器持续鸣叫，松开停止；
  - 三键可同时生效。
- **失败现象排查**：
  1. 按下无反应 → 检查 `fpioa.set_function()` 是否遗漏对应引脚（特别是 KEY2 的 Pin0）。
  2. 灯一直亮/一直灭 → 上下拉配置或判断电平写反了。
  3. 蜂鸣器常响 → KEY2 判断应为 `== 1`；若写成 `== 0` 会默认使能 PWM。
  4. KEY2 无效 → 确认按的是板上标有 KEY2 的按键（GPIO0），且它不是复位键。

2. USB Type-C 连接开发板与电脑，点击 IDE 左下角**连接**。

## 7. 拓展思考

1. **状态翻转（Toggle）**：把"按住才亮"改成"按一下亮、再按一下灭"。提示：需要检测"按下→松开"的边沿，并引入一个布尔变量记录当前状态，同时加入 20ms 延时消抖。
2. **组合键功能**：实现"KEY0 + KEY1 同时按下时蜂鸣器响"，练习多个 `value()` 结果的逻辑与（`and`）运算。
3. **按键密码锁**：记录 KEY0/KEY1 的按下顺序（如"0-0-1-0"），顺序正确就点亮双灯 3 秒，错误则蜂鸣器短叫两声，综合运用本实验和[实验2 蜂鸣器实验](../实验2%20蜂鸣器实验/README.md)的知识。

## 8. 常见问题

**Q1：为什么 KEY0/KEY1 判断 `== 0`，KEY2 却判断 `== 1`？**
A：因为硬件接法不同。KEY0/KEY1 按下接地，配合内部上拉，松开为 1、按下为 0；KEY2 按下接电源，配合内部下拉，松开为 0、按下为 1。判断条件必须跟着硬件走，这也是代码里 `key2` 用 `Pin.PULL_DOWN` 的原因。

**Q2：什么是按键抖动？本例为什么没处理？**
A：机械按键按下瞬间触点会弹跳几毫秒，电平在 0/1 间快速抖动。如果程序对每次抖动都计数，一次按键会被当成多次。本例只是把电平直接映射到 LED/蜂鸣器，抖动时间极短、人眼人耳无法察觉，所以可以不处理；但做计数、状态翻转类逻辑时必须加消抖（延时 20ms 再确认一次）。

**Q3：按 KEY2 时开发板会不会重启或切换启动模式？**
A：不会。KEY2 的"启动模式选择"功能只在**上电或复位的瞬间**生效；程序运行起来之后，GPIO0 就是一个普通输入引脚，随便按。

**Q4：运行程序后 LED 为什么是"按住才亮"，能不能反过来？**
A：可以。把每组 `if/else` 里的 `value(0)` 和 `value(1)` 对调即可，变成"松开亮、按下灭"。

**Q5：三个按键能同时按吗？会不会互相干扰？**
A：能。三个 `if` 是并列关系，每圈循环各自独立判断，互不影响。你按住 KEY0 点灯的同时按 KEY2，蜂鸣器也会响。
