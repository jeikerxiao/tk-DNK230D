# 实验6 呼吸灯实验

> 用 PWM 占空比控制蓝色 LED 亮度，KEY0 加亮、KEY1 减暗，理解 PWM 调光原理。难度：初级

## 1. 例程简介

本例程把蓝色 LED（GPIO59）从普通 GPIO 切换成 **PWM5 输出**，以 200Hz 频率、初始 50% 占空比驱动它；按住 KEY0 占空比每次 +10（灯变亮），按住 KEY1 占空比每次 -10（灯变暗），在 10%~100% 之间循环调节，实现手动"呼吸灯"式的亮度控制。你将深入理解 **PWM 频率、占空比与 LED 亮度的关系**。难度为**初级**，是[实验2 蜂鸣器实验](../实验2%20蜂鸣器实验/README.md)（PWM 发声）的姊妹篇——这次 PWM 用来调光。

## 2. 硬件连接与原理

使用板载资源，无需外接：

| 外设 | 引脚 | 代码中的对象 |
| --- | --- | --- |
| 蓝色 LED | Pin59 → PWM5（注意：不再是 GPIO59！） | `pwm0` |
| 红色 LED | GPIO61（程序开始时置 1 熄灭，防止干扰观察） | `ledr` |
| KEY0 按键 | GPIO34（内部上拉，按下读 0）——加亮 | `key0` |
| KEY1 按键 | GPIO35（内部上拉，按下读 0）——减暗 | `key1` |

### 硬件原理（通俗版）

LED 的亮度取决于流过的电流大小，但 GPIO 只能输出"全亮"（高/低电平）或"全灭"两种状态。想调光怎么办？答案是 **PWM 快速开关**：让引脚以足够高的频率（本例 200Hz，即每秒开关 200 次）在亮与灭之间切换——人眼跟不上这么快的闪烁，看到的只是"平均亮度"。

**占空比**就是这个平均值：一个周期内点亮时间所占的百分比。占空比 10% ≈ 微弱发光，50% ≈ 半亮，100% ≈ 最亮。频率必须够高（一般 >100Hz）才不会看到闪烁感，这也是为什么实验 2 的蜂鸣器用 4KHz（那是为了发声），而调光用 200Hz 就够了。

> [!NOTE]
> 同一个物理引脚 Pin59，在实验 1/3 里被映射成 GPIO59 做开关，本实验被映射成 **PWM5** 输出做调光。FPIOA 映射决定了引脚"是什么"，这就是 K230D 引脚复用的灵活性。

### 新手风险提醒

> [!WARNING]
> - 长按 KEY0/KEY1 时占空比会连续变化，代码用"等待松手"限制了单次按键只改一档，不要删除该逻辑，否则手感会变成"瞬间跳到极值"。
> - LED 亮度调高后长时间观察强光可能刺眼，勿近距离直视。
> - 无需接线；若日后外接 PWM 调光模块，注意扩展引脚为 3.3V 电平。

## 3. 相关前置知识

- **PWM（脉冲宽度调制）**：高速开关引脚电平，用"开"的时间比例控制平均输出功率的技术（详见[实验2 蜂鸣器实验](../实验2%20蜂鸣器实验/README.md)）。
- **频率（本例 200Hz）**：每秒开关周期数。调光时频率高低不影响亮度，只影响是否"看得闪烁"——太低会闪，太高没必要。
- **占空比（duty，本例 10~100）**：一个周期内有效电平的百分比，直接决定平均亮度。
- **视觉暂留**：人眼对光的变化有约几十毫秒的"记忆"，高于约 50~100Hz 的闪烁会被感知为连续光，这是 PWM 调光可行的生理学基础。
- **按键消抖与边沿等待**：延时 20ms 二次确认 + `while key.value()==0: pass` 等松手，保证"按一次改一档"。

## 4. 软件代码逻辑说明

流程：**FPIOA 映射 → 构造按键/LED/PWM 对象 → 主循环按按键增减占空比 → 限幅 → 更新 PWM**。

### 第 1 步：FPIOA 功能映射

```python
fpioa = FPIOA()
fpioa.set_function(34, FPIOA.GPIO34)
fpioa.set_function(35, FPIOA.GPIO35)
fpioa.set_function(59, FPIOA.PWM5)
fpioa.set_function(61, FPIOA.GPIO61)
```

重点：Pin59 映射为 **PWM5**（蓝灯调光），Pin61 仍是 GPIO61（红灯，仅用于熄灭），两个按键照常映射为 GPIO。

### 第 2 步：构造对象

```python
key0 = Pin(34, Pin.IN, pull=Pin.PULL_UP, drive=7)
key1 = Pin(35, Pin.IN, pull=Pin.PULL_UP, drive=7)
ledr = Pin(61, Pin.OUT, pull=Pin.PULL_NONE, drive=7)

pwm0 = PWM(5, 200, duty=50, enable=True)
duty = 50
ledr.value(1) # 关闭红色LED灯，防止干扰
```

- `PWM(5, 200, duty=50, enable=True)`：**PWM 通道 5**、频率 **200Hz**、初始占空比 **50%**、立即使能——蓝灯以半亮度点亮。
- 软件变量 `duty` 记录"目标占空比"，初值与 PWM 一致。
- `ledr.value(1)` 熄灭红灯，方便专注观察蓝灯亮度变化。

### 第 3 步：主循环——按键调节占空比

```python
while True:
    if key0.value() == 0:
        time.sleep_ms(20)              # 消抖
        if key0.value() == 0:
            duty = duty + 10           # KEY0：加亮一档
            while key0.value() == 0:
                pass                   # 等待松手
    elif key1.value() == 0:
        time.sleep_ms(20)
        if key1.value() == 0:
            duty = duty - 10           # KEY1：减暗一档
            while key1.value() == 0:
                pass
```

每按一次键，目标占空比 `duty` 增减 10。

### 第 4 步：限幅保护

```python
    if duty == 0:
        duty = 10
    elif duty == 110:
        duty = 100
```

`duty` 递减到 0 时强制回到 10（因为占空比 0% 等于完全熄灭，本实验保留最低一档亮度）；递增到 110 时压回 100（100% 为最亮上限）。效果是在 **10 ↔ 100** 之间来回封顶。

### 第 5 步：写入 PWM

```python
    if pwm0.duty() != duty:
        pwm0.duty(duty)    # 修改PWM占空比
    time.sleep_ms(10)
```

`pwm0.duty()` 不带参数时**读取**当前占空比，带参数时**设置**新占空比。只有目标值与当前值不同才写入，避免每圈循环都重复操作硬件。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `fpioa.set_function(59, FPIOA.PWM5)` | 把 Pin59 映射为 PWM5 输出 |
| `PWM(5, 200, duty=50, enable=True)` | 创建通道 5、200Hz、50% 占空比的 PWM 并使能 |
| `pwm0.duty()` | 读取当前占空比 |
| `pwm0.duty(n)` | 设置占空比为 n（0~100） |

### 可调参数

- 步进 `+10 / -10`：改小（如 +1）调节更细腻，改大更"跳变"。
- 频率 `200`：改成 50 会看到明显闪烁感，改成 1000 无感知差异——动手试试最能理解频率的意义。
- 限幅值 `10 / 100`：想让灯能完全熄灭，把 `if duty == 0: duty = 10` 这两行删掉即可（0% 全灭）。
- 初始占空比 `duty=50` 和变量 `duty = 50`：两处要同步改，否则第一次按键会突变。

## 5. 运行效果

- **成功现象**：
  1. 运行后蓝灯以约一半亮度点亮，红灯熄灭；
  2. 每按一次 KEY0，蓝灯变亮一档，按到最亮（100%）后不再变化；
  3. 每按一次 KEY1，蓝灯变暗一档，暗到 10% 后不再变化；
  4. 连续快按可以看到亮度平滑过渡，模拟"呼吸"效果。
- **失败现象排查**：
  1. 蓝灯不亮 → 确认 Pin59 映射的是 `FPIOA.PWM5`，且 `PWM(5, ...)` 通道号一致。
  2. 蓝灯闪烁明显 → 频率被改得太低，恢复 200Hz 以上。
  3. 按键无反应 → 检查 GPIO34/35 映射与消抖逻辑；确认按的是 KEY0/KEY1。
  4. 亮度只能单向变化 → 限幅逻辑（0→10、110→100）被改动。

## 7. 拓展思考

1. **自动呼吸灯**：去掉按键逻辑，在主循环里让 `duty` 自动 `+1` 到 100 再 `-1` 到 10 循环变化（每步配合 `time.sleep_ms(20)`），实现真正的自动"呼吸"效果。
2. **呼吸节奏控制**：给自动呼吸灯加入 KEY0"加速"、KEY1"减速"功能（改变每步的延时），综合运用本实验的按键处理框架。
3. **双色渐变**：把红灯（GPIO61）也改映射为某一路 PWM，让蓝灯变亮的同时红灯变暗（占空比互补 `100 - duty`），得到红蓝此消彼长的混色效果。

## 8. 常见问题

**Q1：为什么蓝灯引脚是 59，PWM 通道却是 5？不是 PWM0？**
A：物理引脚号和 PWM 通道号是两套编号。Pin59 通过 FPIOA 被映射成 **PWM5** 功能，所以必须用 `PWM(5, ...)` 操作。实验 2 中蜂鸣器是 Pin60 → PWM0 → `PWM(0, ...)`。规则：**映射哪个 PWM 通道，就实例化几号 PWM**。

**Q2：占空比调到 0 灯全灭，为什么代码又把 0 改回 10？**
A：这是例程故意保留的最低亮度档，方便观察"从暗到亮"的完整调节过程。如果你想让灯彻底熄灭，删掉 `if duty == 0: duty = 10` 即可。

**Q3：变量 `duty` 和 `pwm0.duty()` 是什么关系？**
A：`duty` 是软件里的"目标值"，`pwm0.duty(n)` 是写进硬件的"实际值"。主循环先根据按键更新目标值、限幅，再比较二者，不一致时才写入硬件。这种"目标值-实际值"分离的写法在嵌入式中非常常见。

**Q4：长按按键为什么只变一档，不能连续调？**
A：代码里 `while key0.value() == 0: pass` 会阻塞等待松手，一次按下只执行一次 `duty+10`。想长按连续调节，可以删掉这两处等待循环，并把循环末尾延时改小，亮度就会随长按连续变化。

**Q5：把频率 200 改成 4000 会怎样？**
A：LED 亮度调节功能不变（亮度只由占空比决定），只是开关速度更快。频率高到一定程度后对调光已无感知区别，反而蜂鸣器那种发声场景才需要 4KHz——PWM 的用途由频率的"意义"决定。
