# 实验9 thread实验

> 用 `_thread` 启动两个线程同时打印 "hello 1" 和 "hello 2"，初识多线程并发。难度：中级

## 1. 例程简介

本例程使用 MicroPython 的 **`_thread` 模块**创建两个子线程，两个线程各自每秒打印一次 `hello 1` / `hello 2`，与主线程"同时"运行，终端里两条消息交错出现。你将学会**线程的创建、参数传递、并发执行的概念**，理解它与前面实验中"一个 while 循环干所有事"的写法有何本质不同。难度为**中级**，多线程是后续做"采集 + 显示 + AI 推理并行"类项目的编程基础。

## 2. 硬件连接与原理

本实验**不使用任何引脚、LED、按键或外接模块**，只用到：

| 资源 | 说明 |
| --- | --- |
| CPU | K230D 为 RISC-V **双核**处理器，可支持多线程并发调度 |
| 串口终端 | `print()` 输出到 CanMV IDE 终端 |

所以**没有任何接线**，也不会驱动板上的外设——这是一个纯软件/编程概念实验。

### 原理（通俗版）

**线程（thread）** 可以理解为"程序内部的一条独立执行流"。默认情况下 Python 脚本只有主线程一条执行流，代码从上到下一行行跑；创建新线程后，新线程的函数会和主线程**交替执行**，看起来像"同时在做几件事"。

打个比方：主线程是一个厨师，从"切菜"到"炒菜"必须按顺序做；雇了两个帮厨（子线程）后，一个专门烧水、一个专门摆盘，三件事看起来同时进行。

K230D 是双核 RISC-V 芯片，CanMV 固件的 MicroPython 支持 `_thread` 模块，可以把线程分配到核心上执行，实现真正的并发。本例中两个子线程分别循环打印，主线程则停在空循环里"守住"程序不退出。

### 新手风险提醒

> [!WARNING]
> - 本实验无硬件风险；但多线程程序**调试难度更高**：出错时可能表现为随机死机、打印错乱，新手要先理解概念再动手改。
> - 线程一旦启动**无法从外部强行杀死**（MicroPython 的 `_thread` 没有提供停止接口），只能靠线程函数自己 `return` 退出。想停掉本实验只能停止脚本或复位开发板。
> - 多个线程同时 `print` 到同一串口，极端情况下输出可能交织在一行，这是正常现象。

## 3. 相关前置知识

- **主线程**：脚本从第一行开始执行的那条默认执行流。本例主线程创建完子线程后进入 `while 1: pass`。
- **子线程**：由 `_thread.start_new_thread()` 启动的新执行流，运行你指定的函数。
- **并发（Concurrency）**：多件事在一段时间内交替/同时推进。与"并行"（同一瞬间真的一起做）概念相近但不完全相同；双核 CPU 上两个线程可以真正并行。
- **函数与参数**：`start_new_thread(func, args)` 中 `args` 必须是一个**元组**。`("1",)` 里那个逗号不能少——`("1")` 只是带括号的字符串，`("1",)` 才是含一个元素的元组。
- **格式化字符串**：`"hello {}".format(name)` 把 `{}` 替换为变量 `name` 的值。
- **`time.sleep(1)`**：线程函数里的延时，让每条线程每秒打印一次，也主动让出 CPU 给别的线程。

## 4. 软件代码逻辑说明

代码极短，流程：**定义线程函数 → 启动两个线程 → 主线程空循环守护**。

### 第 1 步：导入模块

```python
import _thread
import time
```

`_thread` 是 MicroPython 内置的底层线程模块（注意开头有下划线）。

### 第 2 步：定义线程函数

```python
def func(name):
    while 1:
        print("hello {}".format(name))
        time.sleep(1)
```

这就是每个子线程要执行的任务：死循环里每秒打印一次 `hello 名字`。参数 `name` 用来区分不同线程的打印内容。

> [!NOTE]
> `while 1` 等价于 `while True`，表示这个函数**永不返回**——线程会一直运行下去，直到脚本被停止或系统复位。

### 第 3 步：启动两个线程

```python
_thread.start_new_thread(func,("1",))
_thread.start_new_thread(func,("2",))
```

`start_new_thread(函数, 参数元组)` 创建并立即启动一个新线程：

- 第一个线程运行 `func("1")`，循环打印 `hello 1`；
- 第二个线程运行 `func("2")`，循环打印 `hello 2`。

两个线程各自独立推进，互不等待。

### 第 4 步：主线程守护

```python
while 1:
    pass
```

主线程如果执行到脚本末尾就结束了，整个程序可能随之终止、子线程被"带走"。所以让主线程停在空死循环里**保持脚本存活**，子线程才能持续打印。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `_thread.start_new_thread(fn, args)` | 启动新线程执行 `fn(*args)`，返回线程 ID |
| `time.sleep(1)` | 让当前线程休眠 1 秒，期间 CPU 可跑其他线程 |

### 可调参数

- 打印内容 `"hello {}"`：任意修改。
- `time.sleep(1)`：改成 0.5 打印频率翻倍；两个线程改成不同延时（需要把延时也做成参数传入），可以看到交错节奏变化。
- 线程个数：再加一行 `start_new_thread(func, ("3",))` 就是三个线程；但线程不是越多越好，每个线程都占内存和调度开销，嵌入式平台上一般 2~4 个为宜。
- 想给函数传多个参数，元组写成 `("1", 2)` 这种多元素形式即可。

## 5. 运行效果

- **成功现象**：IDE 终端每秒交错出现两行打印，顺序大致如下（交错次序可能变化）：

  ```text
  hello 1
  hello 2
  hello 1
  hello 2
  ...
  ```

- **失败现象排查**：
  1. 只打印 `hello 1` 没有 `hello 2`（或反之）→ 检查第二个 `start_new_thread` 是否漏写；参数元组逗号是否正确。
  2. 报 `TypeError` → 常见原因是参数没写成元组：`("1")` 应改为 `("1",)`。
  3. 程序一闪就结束、几乎没打印 → 主线程末尾的 `while 1: pass` 被删掉了。
  4. 报错找不到 `_thread` → 固件不是 CanMV K230D 固件（部分精简固件不含线程模块）。

## 7. 拓展思考

1. **不同节奏的三线程**：给 `func` 增加一个"周期"参数，启动三个线程分别以 0.5s、1s、2s 打印，观察三条执行流交错的时间规律。
2. **线程控制 LED**：结合[实验1 跑马灯实验](../实验1%20跑马灯实验/README.md)，让线程 1 负责红灯每秒翻转、线程 2 负责蓝灯每 0.5 秒翻转，主线程空闲——体会"多线程各管一摊"的写法；注意 FPIOA/Pin 初始化要放在启动线程**之前**。
3. **线程间通信初探**：定义一个全局变量 `flag`，主线程每秒翻转它，子线程根据 `flag` 决定打印 "on" 还是 "off"；思考为什么多个线程同时读写同一变量时需要小心（引出"竞态"概念）。

## 8. 常见问题

**Q1：`("1",)` 里那个逗号为什么不能少？**
A：Python 中 `("1")` 只是加了括号的字符串 `"1"`，而 `("1",)` 才是**只含一个元素的元组**。`start_new_thread` 的第二个参数必须是元组（它会把元组拆开传给函数），少写逗号会报 `TypeError`。这是 Python 语法规定，不是 CanMV 特有的。

**Q2：两个线程的打印顺序为什么有时是 `hello 2` 在前？**
A：线程由系统调度，谁先获得 CPU 执行是不确定的，加上 `print` 经过串口的时机差异，交错顺序每次运行都可能不同。这正说明它们是"并发"的，而不是按启动顺序排队执行。

**Q3：主线程的 `while 1: pass` 可以去掉吗？**
A：不可以。脚本主线程一旦执行完最后一行，整个程序就结束了，子线程也会随之停止。主线程必须保持存活（空循环、`while 1: time.sleep(1)` 或做别的事都行）。

**Q4：怎么停止某个线程？**
A：MicroPython 的 `_thread` **没有提供强制终止线程的接口**。想优雅退出，需要在线程函数里检查一个全局标志变量，为假时 `return` 结束函数，线程自然消亡。本例的死循环线程只能靠停止脚本/复位来结束。

**Q5：多个线程可以同时操作同一个串口/引脚吗？**
A：要谨慎。多线程同时 `print` 一般没问题（输出可能交错）；但同时读写同一个引脚、同一个 UART 缓冲区，可能出现数据竞争。工程上的做法是：一个外设只由一个线程负责，其他线程通过标志变量/队列向它"提需求"。
