# 实验13 文件读写实验

> 按 KEY0 往 TF 卡写文件、KEY1 读出来、KEY2 列目录，学会在开发板上存取数据。难度：初级

## 1. 例程简介

本例程演示 CanMV MicroPython 的**文件系统操作**：TF 卡挂载在 `/sdcard/` 目录下，按 KEY0 把一行文字（带循环计数）写入 `/sdcard/test.txt`，按 KEY1 读出并打印该文件内容，按 KEY2（或程序启动时）用 `uos.listdir()` 列出 TF 卡根目录的所有文件。你将学会 **open/read/write/close 文件四步曲、uos 目录操作、TF 卡挂载路径**，这是数据记录、AI 模型加载、脱机运行程序的基础。难度为**初级**。

## 2. 硬件连接与原理

| 外设 | 引脚/资源 | 代码中的对象 |
| --- | --- | --- |
| KEY0 按键 | GPIO34（上拉输入，按下读 0）——写文件 | `key0` |
| KEY1 按键 | GPIO35（上拉输入，按下读 0）——读文件 | `key1` |
| KEY2 按键 | GPIO0（下拉输入，按下读 1）——列目录 | `key2` |
| TF 卡 | 底板 TF 卡槽，挂载为 `/sdcard/` | 文件路径 `/sdcard/test.txt` |
| USB 串口 | 打印结果 | `print()` |

### 硬件原理（通俗版）

开发板上有两种常见存储：板载 **SD NAND**（焊在板上的存储芯片）和 **TF 卡槽**（插 Micro SD 卡）。KEY2 在**上电瞬间**按住可以选择从哪一种启动。固件会把存储设备**挂载**成一个目录——本例程使用的 TF 卡挂载在 `/sdcard/`，之后对文件的读写就像在电脑上操作文件夹一样，用路径字符串定位：`/sdcard/test.txt` 就是"TF 卡根目录下的 test.txt"。

TF 卡通过 SDIO 接口与芯片通信，文件系统一般是 FAT32/exFAT，MicroPython 的 `open()` 直接按文本方式读写，无需关心底层细节。

### 新手风险提醒

> [!WARNING]
> - **插拔 TF 卡必须断电**！带电插拔可能损坏卡内数据甚至烧毁卡槽。
> - TF 卡插入方向要对准（金手指朝向卡槽触点），推到底听到/感到"咔哒"锁定，取出时轻按弹出。
> - 写文件过程中（按 KEY0 瞬间）拔卡或断电会产生损坏的半截文件。
> - 请使用正规品牌 TF 卡并提前在电脑上格式化为 FAT32。

## 3. 相关前置知识

- **文件系统与路径**：以 `/` 开头的绝对路径表示从根目录找起；`/sdcard/` 是 TF 卡挂载点，`/sdcard/test.txt` 是一个具体文件。
- **文件打开模式**：`'w'` 写模式——文件不存在则新建，**存在则清空原内容重写**；`'r'` 读模式——文件必须已存在，否则报错；（另有 `'a'` 追加模式，本例未用）。
- **`f.close()`**：写完必须关闭文件，数据才保证完整落盘；不关文件还可能占用资源导致后续打开失败。
- **`uos` 模块**：MicroPython 版的操作系统接口模块（对应 CPython 的 `os`），`uos.listdir(path)` 返回该目录下所有文件/文件夹名字的列表。
- **字符串格式化**：`"正点原子 K230D BOX + {}".format(i)` 把 `{}` 替换成计数 `i`，所以每次按键写入的内容都不同，便于验证"真的写进去了"。
- **按键消抖与轮询**：本例用循环末尾 `time.sleep_ms(200)` 降低轮询频率代替严格的消抖（写入/读取动作本身较慢，短暂重复触发影响不大）。

## 4. 软件代码逻辑说明

流程：**FPIOA 映射 → 构造按键 → 打印 TF 卡目录 → 主循环按键读/写/列目录**。

### 第 1 步：FPIOA 映射与按键对象

```python
fpioa = FPIOA()
fpioa.set_function(34, FPIOA.GPIO34)
fpioa.set_function(35, FPIOA.GPIO35)
fpioa.set_function(0, FPIOA.GPIO0)

key0 = Pin(34, Pin.IN, pull=Pin.PULL_UP, drive=7)
key1 = Pin(35, Pin.IN, pull=Pin.PULL_UP, drive=7)
key2 = Pin(0, Pin.IN, pull=Pin.PULL_DOWN, drive=7)
```

三个按键与[实验3 按键输入实验](../实验3%20按键输入实验/README.md)完全一致：KEY0/KEY1 上拉输入按下读 0，KEY2 下拉输入按下读 1。

### 第 2 步：启动时先列一次目录

```python
i = 0
print(uos.listdir("/sdcard/"))
```

程序一运行就打印 TF 卡根目录的文件列表——既是"卡已挂载"的健康检查，也让你先看看卡里有什么。`i` 是写入内容的计数器。

### 第 3 步：主循环——KEY0 写文件

```python
while True:
    if key0.value() == 0:
        f = open('/sdcard/test.txt', 'w') #以写的方式打开一个文件，没有该文件就自动新建
        wr_data = "正点原子 K230D BOX + {}".format(i)
        f.write(wr_data) #写入数据
        f.close() #每次操作完记得关闭文件
        print("write success") #读取数据并在终端打印
        time.sleep_ms(50)
```

文件写入四步曲：**open('w') → write → close → （打印确认）**。注意 `'w'` 模式每次都会**覆盖**旧内容，所以文件里永远只有最后一次写入的那行字。

### 第 4 步：主循环——KEY1 读文件

```python
    if key1.value() == 0:
        f = open('/sdcard/test.txt', 'r') #以读方式打开一个文件
        text = f.read()
        print(text) #读取数据并在终端打印
        f.close() #每次操作完记得关闭文件
        time.sleep_ms(50)
```

读文件三步曲：**open('r') → read() → close()**。`f.read()` 不传参数表示读整个文件，返回字符串。

> [!WARNING]
> 如果从没按过 KEY0（文件不存在）就直接按 KEY1，`open(..., 'r')` 会抛出 `OSError`（文件不存在），脚本中断。先写后读。

### 第 5 步：主循环——KEY2 列目录 + 计数

```python
    if key2.value() == 1:
        print(uos.listdir("/sdcard/"))
        time.sleep_ms(50)
    time.sleep_ms(200)
    i = i + 1
```

KEY2 按下（读 1）随时列出 TF 卡目录，能看到 `test.txt` 出现。循环末尾延时 200ms 并让计数 `i` 自增——所以每次按 KEY0 写入的文字末尾数字都不同。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `open(路径, 'w')` | 新建/清空并以写模式打开文件 |
| `open(路径, 'r')` | 以读模式打开已存在的文件 |
| `f.write(字符串)` | 写入内容 |
| `f.read()` | 读取全部内容 |
| `f.close()` | 关闭文件，确保落盘 |
| `uos.listdir("/sdcard/")` | 列出目录下所有文件名 |

### 可调参数

- 文件路径 `/sdcard/test.txt`：可改名或建子目录（如 `/sdcard/data/log.txt`，注意**子目录要先用 `uos.mkdir()` 创建**）。
- 写入内容 `"正点原子 K230D BOX + {}"`：任意修改；想保留历史记录可把 `'w'` 改成 `'a'`（追加模式），每按一次 KEY0 就多一行。
- `time.sleep_ms(200)`：轮询间隔，改小按键响应更快。

## 5. 运行效果

- **成功现象**：
  1. 运行瞬间终端打印 TF 卡根目录文件列表（如 `['test.txt', 'app', ...]`，新卡可能是空列表 `[]`）；
  2. 按 KEY0：打印 `write success`；
  3. 按 KEY1：打印 `正点原子 K230D BOX + 数字`（与最近一次写入一致）；
  4. 按 KEY2：再次打印目录列表，写过后能看到 `test.txt`；
  5. 把 TF 卡拔下插到电脑上（先停止程序、断电拔卡），能看到 test.txt 且内容一致。
- **失败现象排查**：
  1. 启动即报 `OSError` → TF 卡没插好或没格式化为 FAT32；断电重插/格式化。
  2. 按 KEY1 报错 → 文件还不存在，先按 KEY0 写一次。
  3. 按键无反应 → 检查 GPIO34/35/0 映射；KEY2 判断是 `== 1`。
  4. 电脑上看到文件内容乱码 → 文件以 UTF-8 编码写入，电脑记事本请选择 UTF-8 打开。

## 6. 代码使用说明

1. **断电**后将 TF 卡（建议 FAT32 格式，≤32GB 兼容性最好）插入底板 TF 卡槽。
2. 用 **CanMV IDE** 打开本目录下的 `main.py`，USB Type-C 连接开发板，点击**连接**、**运行**。
3. 依次按 KEY0（写）→ KEY1（读）→ KEY2（列目录）验证功能。
4. 固件要求：**CanMV K230D 固件**，版本与 IDE 匹配。
5. 本实验**需要 TF 卡**（挂载点 `/sdcard/`），不需要模型文件。

> [!NOTE]
> 若你选择从板载 SD NAND 启动，SD NAND 同样会挂载为 `/sdcard/` 供应用读写，本例程代码不用改；TF 卡与 SD NAND 的使用取决于 KEY2 启动模式选择（上电瞬间按住 KEY2 切换）。以代码中的实际路径 `/sdcard/` 为准即可。

## 7. 拓展思考

1. **数据记录仪**：把 `'w'` 改成 `'a'`（追加），每按一次 KEY0 追加一行"计数 + 时间"（结合[实验7 RTC实验](../实验7%20RTC实验/README.md)），做成简易事件日志。
2. **配置加载器**：手工在电脑往 TF 卡写一个 `config.txt`（如内容 `5`），程序启动时读出来作为跑马灯的闪烁间隔——体验"用文件配置程序行为"。
3. **脱机运行自己的程序**：把任意实验的 `main.py` 复制到 TF 卡 `/sdcard/app/main.py`，上电后开发板会自动运行它，不再依赖电脑和 IDE；这是产品化部署的第一步。

## 8. 常见问题

**Q1：`/sdcard/` 是哪个卡？我插了 TF 卡怎么还报错？**
A：`/sdcard/` 是固件对"当前启动/数据存储设备"的挂载路径，可能对应 TF 卡或板载 SD NAND（由 KEY2 上电时的启动模式决定）。报错常见原因：卡没插到位、卡未格式化为 FAT32、或带电插拔导致卡进入异常状态——断电重插一般可解决。

**Q2：为什么每次按 KEY0 再按 KEY1，读到的只有最新一句话？**
A：因为 `open(..., 'w')` 是**覆盖写**：每次打开都把文件清空重写。想累积保存历史，请改用追加模式 `open(..., 'a')`。

**Q3：写文件后马上拔卡，电脑上能看到内容吗？**
A：不一定。`f.close()` 执行后数据才保证写入卡中，但拔卡前还应先停止程序、给系统一点时间完成缓存刷写。最稳妥流程：停止脚本 → 断电 → 拔卡。

**Q4：`print(uos.listdir("/sdcard/"))` 打印出来是空的 `[]`，正常吗？**
A：正常，说明卡挂载成功但根目录还没有文件。按一次 KEY0 再按 KEY2，就能看到 `test.txt` 出现。如果这一步直接抛异常，才是挂载/卡的问题。

**Q5：能往 `/sdcard/` 里放图片、模型文件吗？**
A：可以。`/sdcard/` 就是普通文件系统，AI 例程的模型文件、图片、视频一般都放这里（如拍照实验用的是 `/data/` 分区，视频播放器读取 `/data/VIDEO/test.mp4`）。注意固件分区各有容量上限，大文件优先放 TF 卡。
