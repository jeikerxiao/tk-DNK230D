# 实验2 蜂鸣器实验

> 用 PWM 输出 4KHz 方波，让板载蜂鸣器持续鸣叫，第一次接触"模拟"世界。难度：入门

## 1. 例程简介

本例程通过 K230D 的 **PWM（脉宽调制）** 功能，在 Pin60 上输出一个频率为 **4KHz、占空比 50%** 的方波信号，驱动开发板板载蜂鸣器发出持续的"滴——"声。你将学到 PWM 的基本概念、FPIOA 功能映射以及 `machine.PWM` 类的使用。难度为**入门**，预期用途是掌握"用数字引脚产生声音"这一常用技能（报警器、提示音等）。

## 2. 硬件连接与原理

本实验**不需要外接任何模块**，使用板载资源：

| 外设 | 引脚 | 代码中的对象 |
| --- | --- | --- |
| 板载蜂鸣器 | 由 Pin60 输出的 PWM0 信号驱动 | `pwm0` |

### 硬件原理（通俗版）

`main.py` 文件头部注释明确写着：

> K230D-BOX 使用的是无源蜂鸣器，无源蜂鸣器规格书要求震荡频率为 4KHz

**无源蜂鸣器**（"无源"指内部没有振荡电路）本质上是一个微型电磁扬声器：给它通直流电它只会"咔哒"一声，必须给它一个**一定频率的交变方波**，内部振片才会按该频率振动发声。给它 4KHz 的方波，它就发出 4KHz 音调的鸣叫；改变方波频率，音调也会跟着改变。

PWM 输出的正是方波：引脚在高电平（3.3V）和低电平（0V）之间高速来回切换。每秒切换 4000 次就是 4KHz；一个周期内高电平所占时间的百分比就是**占空比**，50% 表示高低各一半，声音最响亮对称。

### 新手风险提醒

> [!WARNING]
> - 蜂鸣器声音较尖锐，长时间近距离鸣叫可能刺耳，测试时可适当远离或缩短运行时间。
> - 运行程序后蜂鸣器会**一直响**（主循环是 `while True: pass`），想让它停下来请在 IDE 点击停止，或按开发板复位键。
> - 不要自行把蜂鸣器两端直接接到 3.3V/5V 电源上长时间通电，无源蜂鸣器直流长时间通电可能发热损坏。

## 3. 相关前置知识

- **PWM（脉冲宽度调制）**：一种"用数字引脚模拟模拟效果"的技术。引脚快速地开开关关，通过调节一个周期内"开"的时间比例（占空比）或开关的快慢（频率），可以控制电机转速、LED 亮度、声音音调等。
- **频率（Hz）**：方波每秒钟重复的次数。4KHz = 每秒 4000 个周期。频率决定声音的**音调**高低。
- **占空比（duty）**：一个周期内高电平时间的百分比，范围 0~100。50% 表示高低电平各占一半。占空比影响声音的**响度**与音色。
- **有源蜂鸣器 vs 无源蜂鸣器**：有源蜂鸣器内部自带振荡电路，通电即响；无源蜂鸣器需要外部提供振荡方波。本板使用的是**无源蜂鸣器**，所以必须用 PWM。
- **FPIOA**：K230D 的引脚功能映射器，把物理引脚 Pin60 映射成 PWM0 输出通道后才能工作（参见[实验1 跑马灯实验](../实验1%20跑马灯实验/README.md)中的介绍）。

## 4. 软件代码逻辑说明

代码非常短，流程：**导入模块 → FPIOA 映射 → 实例化 PWM → 空循环保持**。

### 第 1 步：导入模块

```python
from machine import PWM
from machine import FPIOA
import time
```

`PWM` 是 MicroPython 官方的 PWM 类，`time` 本例导入了但主循环未用到延时。

### 第 2 步：FPIOA 功能映射

```python
fpioa = FPIOA()
fpioa.set_function(60, FPIOA.PWM0)
```

把物理引脚 Pin60 映射为 **PWM0** 通道输出。注意这里映射的是 `FPIOA.PWM0` 而不是 `FPIOA.GPIO60`——蜂鸣器不是简单的开关量，而是需要 PWM 波形。

### 第 3 步：实例化 PWM 并启动

```python
pwm0 = PWM(0, 4000, duty=50, enable=True)
```

这一行是核心，参数含义：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| 第 1 个参数 | `0` | PWM 通道号（与 FPIOA 映射的 PWM0 对应） |
| 第 2 个参数 | `4000` | 频率 4000Hz（4KHz，蜂鸣器规格书要求的振荡频率） |
| `duty` | `50` | 占空比 50% |
| `enable` | `True` | 创建后立即使能输出 |

### 第 4 步：主循环

```python
while True:
    pass
```

PWM 一旦使能，波形由**硬件自动持续输出**，不需要软件参与。主循环只是让脚本不退出（脚本一旦结束，资源可能被释放，蜂鸣器会停止）。

### 关键 API 小结

| API | 作用 |
| --- | --- |
| `fpioa.set_function(60, FPIOA.PWM0)` | 将 Pin60 映射为 PWM0 输出 |
| `PWM(通道, 频率, duty=占空比, enable=是否使能)` | 创建并配置 PWM 对象 |
| `pwm0.enable(True/False)` | 启动/停止波形输出（本例未调用，见拓展） |

### 可调参数

- 频率 `4000`：改大音调变尖，改小音调变低沉。偏离 4KHz 太多时声音会明显变小（蜂鸣器在谐振频率附近最响）。
- `duty=50`：改成 20、80 等，响度和音色会变化；改成 0 或 100 相当于恒定电平，蜂鸣器不响。
- `enable=True`：改成 `False` 则程序运行后不发声，需要手动调用 `pwm0.enable(True)` 才开始响（这正是[实验3 按键输入实验](../实验3%20按键输入实验/README.md)中蜂鸣器的用法）。

## 5. 运行效果

- **成功现象**：程序运行后，板载蜂鸣器立即发出持续的、音调较尖的"滴——"声，直到程序停止；IDE 串口终端无打印、无报错。
- **失败现象排查**：
  1. 没有声音 → 确认 IDE 已成功连接并运行脚本；确认固件为 CanMV K230D 固件。
  2. 只有"咔哒"一声后无声 → 频率参数被改成了极低值，或被映射成 GPIO 输出了固定电平。
  3. 声音很小 → 频率偏离 4KHz 太多，或占空比不是 50%。
  4. 报错 `ValueError` → PWM 通道号与 FPIOA 映射不一致（映射 PWM0 就必须实例化 `PWM(0, ...)`）。

## 6. 代码使用说明

1. 打开 **CanMV IDE**，加载本目录下的 `main.py`。
2. USB Type-C 线连接开发板与电脑，点击 IDE 左下角**连接**按钮。
3. 点击**运行**，听到持续鸣叫即为成功；点击**停止**或按复位键结束。
4. 固件要求：**CanMV K230D 固件**，版本与 IDE 匹配（建议使用正点原子出厂配套固件）。
5. 本实验**不需要 TF 卡、不需要模型文件**。

> [!NOTE]
> 由于脚本运行期间蜂鸣器一直响，调试时若想安静一些，可以把 `enable=True` 改为 `enable=False`，运行后在 IDE 交互式终端手动输入 `pwm0.enable(True)` / `pwm0.enable(False)` 来控制发声时机。

## 8. 常见问题

**Q1：为什么蜂鸣器要用 PWM，直接输出高电平不行吗？**
A：不行。本板是**无源蜂鸣器**，内部没有振荡电路，接直流电平只会轻微"咔哒"一声。必须给它 4KHz 左右的方波让它持续振动才能连续发声，这正是 PWM 的功能。

**Q2：`PWM(0, 4000, ...)` 的第一个 `0` 和引脚号 `60` 是什么关系？**
A：两个不同的编号体系。`0` 是 **PWM 通道号**，`60` 是**物理引脚号**。通过 `fpioa.set_function(60, FPIOA.PWM0)` 把"PWM0 通道的波形"送到"Pin60 引脚"上，两者必须配套：映射 PWM0 就要用通道 0，映射 PWM1 就要用通道 1。

**Q3：程序停止后蜂鸣器偶尔还会响一下，正常吗？**
A：正常。停止脚本或复位瞬间引脚状态切换，蜂鸣器可能有短暂的"咔哒"声，属于电路瞬态现象，不是故障。

**Q4：改变占空比为什么声音大小会变？**
A：占空比 50% 时方波正负"能量"最平衡，蜂鸣器振动幅度最大、最响。占空比偏离 50%（如 10% 或 90%）时，等效交流分量变小，声音就变弱；0% 或 100% 时变成纯直流，完全无声。

**Q5：能不能同时用多个 PWM 通道？**
A：可以，K230D 芯片提供多路 PWM。但本板的蜂鸣器只接在 PWM0/Pin60 这一路上，其他通道需要外接设备才能观察到效果，且注意扩展引脚为 3.3V 电平。
