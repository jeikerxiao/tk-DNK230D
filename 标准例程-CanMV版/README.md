## 1. 项目简介

**DNK230D（K230D BOX）** 是正点原子推出的一款基于嘉楠 **K230D** 芯片的 AI 视觉开发板：

| 项目 | 说明 |
| --- | --- |
| 主控芯片 | 嘉楠 K230D，**RISC-V** 架构双核处理器 |
| AI 算力 | 内置 **KPU**（神经网络加速器），约 6TOPS 算力 |
| 开发方式 | **CanMV IDE** + **MicroPython**，无需写 C 代码 |
| 应用场景 | 人脸识别、物体检测、手势识别、循迹小车、语音唤醒等 |

> [!NOTE]
> **名词解释（零基础必看）**
> - **RISC-V**：一种开源免费的处理器指令集架构，可以理解为"芯片听得懂的语言标准"，与 ARM 类似。
> - **KPU**：K230D 芯片里专门用来跑 AI 神经网络模型的"加速器"。CPU 算 AI 很慢，KPU 算 AI 又快又省电。
> - **TOPS**：每秒万亿次运算，衡量 AI 算力的单位。6TOPS 意味着每秒能做 6 万亿次运算。
> - **MicroPython**：Python 语言的精简版，专门跑在单片机/嵌入式芯片上，语法和 Python 3 基本一致。
> - **CanMV**：嘉楠官方的 MicroPython 开发框架，**CanMV IDE** 是配套的电脑端开发工具（写代码、下载、调试、看摄像头画面）。

**这套例程适合谁？**

- 想入门 **嵌入式 AI / 机器视觉**，但没有 AI 基础的初学者；
- 会一点 Python，想玩硬件（摄像头、屏幕、AI 推理）的同学；
- 电子、自动化、计算机专业做课程设计 / 毕业设计的同学；
- 创客、DIY 爱好者（视觉循迹小车、人脸门禁都能做）。

## 2. 硬件介绍

### 2.1 板卡组成

K230D BOX 由两块板子组成：

```
┌─────────────────────────────┐
│   CNK230DF 核心板（邮票孔）    │  ← K230D 芯片、内存、SD NAND 都在这
├─────────────────────────────┤
│   DNK230D 底板               │  ← 屏幕、摄像头、按键、LED 等外设都在这
└─────────────────────────────┘
```

- **CNK230DF 核心板**：搭载 K230D 主控芯片、DDR 内存、SD NAND Flash（板载存储，可以不放 TF 卡也能启动运行）。
- **DNK230D 底板**：引出所有外设接口，是实验的主战场。

### 2.2 底板外设清单

| 外设 | 规格 / 说明 |
| --- | --- |
| LCD 显示屏 | **2.4 寸 MIPI 接口屏**，带电容触摸屏 |
| 摄像头 | **两路 MIPI CSI 摄像头接口**（双摄） |
| 按键 | **3 个按键**（KEY0 / KEY1 / KEY2，其中 KEY2 兼作启动模式选择） |
| LED | **双色 LED**（红 / 蓝，红色接 GPIO61，蓝色接 GPIO59） |
| 蜂鸣器 | 无源蜂鸣器，PWM 驱动发声（可控制音调） |
| 存储 | **TF 卡槽**（支持从 TF 卡启动 / 存放模型文件） |
| 串口 | UART 接口，用于 IDE 通信、串口打印、与单片机通信 |
| ADC | 模数转换接口，读取模拟电压（如电位器） |
| 扩展 GPIO | 引出多个 IO 口，可接舵机、电机驱动等扩展模块 |
| 音频 | 板载麦克风（录音、语音唤醒实验用） |

> [!NOTE]
> **MIPI 是什么？** MIPI 是一种高速串行接口标准，屏幕（MIPI DSI）和摄像头（MIPI CSI）都用它传数据，特点是线少、速度快。它是板子内部已经连好的，你不需要"接线"，只需要在代码里选对设备号。

### 2.3 硬件接线注意事项（新手避坑清单）

> [!WARNING]
> **摄像头排线插反会烧坏！** MIPI 摄像头排线（FPC 软排线）有正反方向：金属触点面朝向底座触针。插反后上电可能直接烧毁摄像头或主板接口。插之前先看丝印和卡扣方向，插好后轻拉确认锁紧，**必须断电操作**。

> [!WARNING]
> **供电要求**：请使用配套的 5V/2A（或以上）电源适配器或 USB 线供电。AI 推理 + 屏幕 + 双摄同时工作时电流较大，供电不足会导致反复重启、IDE 掉线。不要从电脑低功率 USB 口带大负载外设。

**启动方式选择（KEY2）**：

板子支持两种启动介质：

| 启动方式 | 说明 |
| --- | --- |
| **SD NAND 启动** | 固件烧在板载 SD NAND 里，上电即运行，适合脱机使用 |
| **TF 卡启动** | 固件烧在 TF 卡里，插卡启动，适合频繁换固件 |

**操作方法**：按住 **KEY2** 再上电（或复位），可进入 / 切换启动模式选择，具体以正点原子教程文档为准。

**其他避坑点**：

1. **先断电再插拔**摄像头、屏幕排线、TF 卡，热插拔易损坏接口。
2. **TF 卡文件系统**建议 FAT32，模型文件一般放在 TF 卡（挂载后路径为 `/sdcard/`）。
3. **屏幕排线**很脆，拆装时不要硬掰，卡扣先翻开再抽排线。
4. **ADC 引脚**只能接 0~3.3V 电压，切勿接 5V，会烧引脚。
5. 扩展 GPIO 输出电压为 **3.3V 电平**，与 5V 单片机（如 STM32 的 5V 容忍引脚除外）连接时注意电平匹配。
6. 板子运行 AI 例程时**发热属正常现象**，不要覆盖散热面。

## 3. 前置环境准备

### 3.1 下载 CanMV IDE

1. 访问嘉楠 CanMV 官网或正点原子资料盘，下载 **CanMV IDE（K230D 版本）**；
2. Windows 用户直接安装，Linux/macOS 用户按官方说明安装；
3. 首次打开可能提示安装驱动（用于识别开发板串口），按提示安装即可。

> [!WARNING]
> **固件与 IDE 版本必须匹配！** CanMV 固件更新较快，旧 IDE 连新固件（或反过来）会出现"能识别串口但连不上板子"的问题。请使用正点原子资料盘中配套的 IDE + 固件组合，或都升级到官方最新配套版本。

### 3.2 烧录固件

两种方式二选一：

**方式 A：烧录到板载 SD NAND（推荐，脱机可用）**

1. 下载正点原子提供的 **SD NAND 版固件**（`.img` 或官方烧录包）；
2. 按正点原子《固件烧录》教程，用烧录工具将固件写入板载 SD NAND；
3. 烧录完成后复位，板子自动运行 `/sdcard`（即 SD NAND 数据分区）中的 `main.py`。

**方式 B：烧录到 TF 卡**

1. 准备一张 8GB 以上的 TF 卡（建议 Class10）；
2. 用烧录工具将 **TF 卡版固件** 写入 TF 卡；
3. 插入板子，按 KEY2 选择 TF 卡启动。

### 3.3 连接设备

1. 用 **Type-C 数据线**（注意必须是数据线，不能是纯充电线）连接开发板与电脑；
2. 打开 CanMV IDE，点击左下角 **连接按钮**，选择识别到的串口；
3. 连接成功后，IDE 底部显示固件版本信息，即可打开例程 `main.py` 点击运行。

**串口识别问题**：

- Windows：设备管理器中出现 CH340/CP210x 串口即正常；带感叹号说明驱动没装好；
- 识别不到串口：换数据线、换 USB 口、重装驱动；
- Linux 下串口名为 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。

## 4. 学习路线

按下面 5 个阶段循序渐进，每个阶段的例程都在本仓库中，点链接即可进入对应教程。

### 阶段 1：基础外设入门（熟悉 IO、延时、屏幕）

学会控制 LED、蜂鸣器、按键，理解 GPIO、定时器、串口等嵌入式最基础的概念，最后点亮 LCD 屏幕。

> 跑马灯 → 蜂鸣器 → 按键输入 → WDT → Timer → 呼吸灯 → RTC → UART → thread → LCD → 触摸屏

### 阶段 2：摄像头与图像基础

第一次让摄像头画面出现在屏幕上，学习在图像上画线画框，理解"帧"和"图像算法"的概念，掌握颜色阈值追踪。

> 摄像头实验 → image 元素绘制 → 边缘检测 → 直线/线段/圆形/矩形检测 → 单/多颜色识别 → 色块计数 → 色块追踪 → 文件读写 → 拍照

### 阶段 3：特征识别

识别图中具有特定"图案特征"的目标：循线（找黑线）、二维码、条形码、AprilTag、DM 码。

> 快速线性回归（循线）→ 黑线循迹 → 二维码识别 → 条形码识别 → AprilTag 码识别 → DM 码识别

### 阶段 4：KPU AI 推理

使用 K230D 的 KPU 神经网络加速器运行 AI 模型：人脸、人体、手掌、手势、物体检测与分割、车牌识别。

> 人脸检测 → 人脸关键点 → 人脸姿态 → 人脸识别 → 人体检测 → 人体关键点 → 跌倒检测 → 手掌检测 → 手势识别 → 手掌关键点 → 手掌关键点分类 → 动态手势识别 → 局部放大器 → 物体检测 → 物体分割 → 车牌检测 → 车牌号识别

### 阶段 5：综合项目

把前面的知识组合成完整应用：猜拳游戏（手势 + 游戏逻辑）、关键词语音唤醒（音频 + AI）、自分类学习（在线训练）、录音机、视频播放器。

> 猜拳游戏 → 关键词唤醒 → 自分类学习 → 录音机 → 视频播放器

**在此基础上你还可以做出**：视觉循迹小车（摄像头 + 循线算法 + 扩展 IO 驱动电机）、人脸门禁（人脸识别 + UART 控制继电器/舵机）、姿态识别互动装置等。

## 7. 常见问题 FAQ

**Q1：IDE 无法连接开发板？**

1. 检查数据线（很多 Type-C 线只能充电不能传数据）；
2. 检查串口驱动是否安装（设备管理器有无感叹号）；
3. 确认固件与 IDE 版本匹配；
4. 按住板上复位键再松开，重新点击连接。

**Q2：摄像头黑屏 / 报错？**

1. 断电检查摄像头排线是否插紧、方向是否正确（触点朝向）；
2. 确认代码中选择的 sensor 设备号与实际插入的接口一致；
3. 供电是否充足（电流不足时摄像头初始化失败）。

**Q3：屏幕不亮？**

1. 检查屏幕排线是否松动；
2. 确认代码中 LCD 初始化参数（尺寸/方向）与例程一致；
3. 若运行脱机 `main.py` 不亮但 IDE 运行时亮，检查启动模式与脚本保存位置。

**Q4：TF 卡启动失败？**

1. TF 卡是否用官方工具完整烧录固件（不是简单拷贝文件）；
2. 是否通过 KEY2 选择了 TF 卡启动模式；
3. 换一张质量好的 TF 卡（杂牌卡兼容性差）。

**Q5：AI 例程报模型加载错误（如打不开 .kmodel）？**

1. 模型文件是否已放到正确路径（多数例程从 `/sdcard/` 读取，见各例程 README 的"代码使用说明"）；
2. 模型文件传输是否完整（重新拷贝一次）；
3. 固件版本是否过旧，不支持该模型格式。

**Q6：画面识别卡顿、帧率低？**

1. 属正常现象：AI 推理比普通图像算法耗时，帧率会明显下降；
2. 可在代码中降低摄像头分辨率或缩小 ROI 提高速度；
3. 确认模型运行在 KPU 上而不是 CPU 上（本仓库例程默认已使用 KPU）。

**Q7：代码一运行就复位 / 重启？**

1. 供电不足（换 5V/2A 以上电源）；
2. 内存不足：关闭 IDE 中多余的大图像预览，或降低分辨率；
3. 若启用了 WDT 例程的看门狗，喂狗超时会主动复位，属预期行为。
