# 实验9 多颜色识别实验

> 同时识别红、绿、蓝三种颜色，并用对应颜色的框分别标出，是颜色分拣项目的雏形。难度：**初级**

## 1. 例程简介

本例程用 for 循环对红、绿、蓝三组 LAB 阈值分别调用 `img.find_blobs()`，把检出的色块用**与目标同色**的矩形框标出（红物红框、绿物绿框、蓝物蓝框），串口打印帧率。学习知识点是多阈值管理、循环查找、框色与类别的对应关系。难度为**初级**（在实验8 单颜色识别基础上加一层循环），预期用途是颜色分拣小车、"识别物体是什么颜色"类项目。

## 2. 硬件连接与原理

用到的外设（以 main.py 实际代码为准）：

| 外设 | 代码依据 | 说明 |
| --- | --- | --- |
| MIPI CSI 摄像头 | `Sensor(width=1280, height=960)`，`set_framesize(Sensor.VGA)`，`set_pixformat(Sensor.RGB565)` | 输出 VGA（640x480）RGB565 **彩色**图像 |
| 2.4 寸 MIPI LCD | `Display.init(Display.ST7701, width=640, height=480, fps=90, to_ide=True)` | ST7701 驱动，同步输出 IDE |

原理通俗讲解：find_blobs 的阈值参数是一个**列表**，可以一次传入多组阈值同时找多种颜色；本例的写法是另一种思路——外层 for 循环 i=0,1,2，每轮只用一组阈值查一次。这样做的最大好处是**知道每个色块属于哪种颜色**（i 就是颜色编号），可以直接用 `color[i]` 画出对应颜色的框，便于区分和后续分类处理。

> [!WARNING]
> 新手风险提醒：摄像头/LCD 排线必须**断电插拔**，插反可能烧毁器件；使用 5V/2A 以上稳定电源。

## 3. 相关前置知识

- **LAB 颜色空间**：L 亮度（0~100）、A 红绿轴（-128~127，正偏红负偏绿）、B 黄蓝轴（正偏黄负偏蓝）。把亮度和色彩分开，对光照变化比 RGB 更鲁棒。
- **颜色阈值六元组 (l_lo, l_hi, a_lo, a_hi, b_lo, b_hi)**：L、A、B 三个通道各自的最小/最大值，像素三通道都落在区间内才算命中。
- **thresholds 列表**：本例存了 3 组阈值，`thresholds[i]` 的 i 就是颜色编号（0 红、1 绿、2 蓝）。
- **color 列表**：画框颜色 `(255,0,0)/(0,255,0)/(0,0,255)` 与阈值一一对应，实现"什么颜色用什么框"。
- **blob（色块）**：一片连通命中像素，`blob[0]~blob[3]` 是外接矩形 x、y、w、h。
- **pixels_threshold=200**：像素数少于 200 的色块丢弃，过滤噪点。
- **帧率 FPS**：clock 对象统计；循环 3 次 find_blobs，帧率会比单颜色略低。

## 4. 软件代码逻辑说明

### 第一步：定义三组阈值与对应框色

```python
# 颜色识别阈值(l_lo, l_hi, a_lo, a_hi, b_lo, b_hi)即LAB模型
thresholds = [(0, 80, 20, 127, -10, 30), # 红色
              (0, 80, -120, -10, 0, 30), # 绿色
              (0, 80, 0, 90, -128, -20)] # 蓝色

color = [(255,0,0), (0,255,0), (0,0,255)]
```

注意本例红色阈值的 A 下限是 20（实验8 中是 40），范围更宽，橙红/偏粉也更容易命中。

### 第二步：初始化摄像头与显示

```python
sensor = Sensor(width=1280, height=960) # 构建摄像头对象
sensor.reset()  # 复位和初始化摄像头
sensor.set_framesize(Sensor.VGA)    # 设置帧大小VGA(640x480)，默认通道0
sensor.set_pixformat(Sensor.RGB565) # 设置输出图像格式，默认通道0

Display.init(Display.ST7701, width=640, height=480, fps=90, to_ide=True)
MediaManager.init() # 初始化media资源管理器
sensor.run() # 启动sensor
clock = time.clock() # 构造clock对象
```

### 第三步：主循环——三种颜色逐一查找

```python
while True:
    os.exitpoint() # 检测IDE中断
    clock.tick()   # 记录开始时间（ms）
    img = sensor.snapshot() # 从通道0捕获一张图

    for i in range(3):
        blobs = img.find_blobs([thresholds[i]], pixels_threshold=200) # 0,1,2分别表示红，绿，蓝色。
        for blob in blobs:
            img.draw_rectangle(blob[0], blob[1], blob[2], blob[3], color=color[i], thickness=4)

    # 显示图片
    Display.show_image(img)
    print(clock.fps()) # 打印FPS
```

关键函数说明：

- `for i in range(3)`：i 依次取 0、1、2，代表红、绿、蓝。
- `img.find_blobs([thresholds[i]], pixels_threshold=200)`：每轮用一组阈值查找该颜色的所有色块；参数含义与实验8 相同。
- `img.draw_rectangle(blob[0], blob[1], blob[2], blob[3], color=color[i], thickness=4)`：用该颜色专属的框色画出外接矩形，宽 4 像素。

> [!NOTE]
> 也可以写成一次调用 `img.find_blobs(thresholds, ...)` 同时找三色，但那样无法直接区分 blob 属于哪组阈值（需要自己比对），循环写法牺牲一点速度换来清晰的类别对应。

### 第四步：异常处理与资源释放

`finally` 中依次 `sensor.stop()` → `Display.deinit()` → `MediaManager.deinit()`。

**可调参数**：
- `thresholds` 三组六元组（第 26~28 行）：**务必用 IDE 阈值编辑器按自己环境重新取**，每种颜色各取一次。
- `pixels_threshold=200`：小目标调小、噪点多调大。
- 想加黄色/紫色：往 thresholds 和 color 各追加一项，把 `range(3)` 改成 `range(len(thresholds))`。

## 5. 运行效果

- **屏幕画面**：LCD 与 IDE 显示彩色实时画面；红、绿、蓝三色物体同时出现时，分别被套上红、绿、蓝三色矩形框，互不混淆；移动物体框实时跟随。
- **串口打印**：每帧打印一次帧率数字（比实验8 略低，因为每帧做了 3 次 find_blobs）。
- **成功现象**：三块不同颜色的色卡（或红/绿/蓝积木）放在镜头前，各自被同色框稳定框住，无交叉误检。
- **失败现象排查**：
  - 某种颜色找不到 → 该组阈值与环境不匹配，单独重新取这一组阈值；
  - 红色物体被绿框框住 → 阈值区间过宽导致命中错组，收紧各组的 A/B 通道范围；
  - 白色/黑色物体也被框 → L 通道范围太宽（本例 L 都是 0~80），把上限调低或收紧 A、B。

## 6. 代码使用说明

1. 用 **CanMV IDE** 打开本文件夹 `main.py`（IDE 与板载 **CanMV K230D 固件**版本需匹配）。
2. USB 连接开发板，点击 IDE 连接按钮，再点击运行。
3. 逐色取阈值：IDE"工具 → 机器视觉 → 阈值编辑器"，选帧缓冲区为图像源，分别对着红、绿、蓝物体拖动滑块取值，替换第 26~28 行。
4. LCD 与 IDE 同步显示，串口终端打印帧率。
5. 本例程**不需要额外文件**、无 SD 卡依赖；脱机自启动将 main.py 放入 TF 卡 `/sdcard/`。

> [!NOTE]
> 测试道具推荐：彩色积木、彩色打印色卡、彩色便签纸。三种颜色饱和度越高越好识别，避免暗红/墨绿这类低饱和色。

## 7. 拓展思考

1. **颜色分类输出**：在循环里记录每种颜色的色块数量，帧末打印 `R:2 G:1 B:0` 这样的统计行，或用 `draw_string_advanced` 显示在画面上，做"颜色点数器"。
2. **颜色分拣逻辑**：找到红色色块时把 `blob.cx()` 偏差通过 UART 发给小车，让小车把红色物体推向左边、其他颜色推向右边，模拟分拣流水线。
3. **扩展第四种颜色**：新增黄色阈值（A 小正值、B 大正值，用阈值编辑器取），追加到 thresholds/color 并把循环改为 `range(len(thresholds))`，体会代码的通用写法。

## 8. 常见问题

**Q1：三种颜色同时识别，帧率会不会掉到三分之一？**
A：不会那么夸张。find_blobs 单次开销与命中像素量和搜索范围有关，三组阈值分开查确实约为 3 倍的颜色比较开销，但 VGA 下一般仍能保持可用帧率；若太慢可改 `Sensor.QVGA` 或加 roi。

**Q2：为什么红色物体有时同时被红框和绿框框住？**
A：说明红色阈值和绿色阈值区间有重叠（常见于 A 通道边界）。用阈值编辑器分别重新取值，确保红组 A 下限大于绿组 A 上限，区间互不重叠。

**Q3：thresholds 里的红色 A 下限为什么本例是 20，实验8 是 40？**
A：不同例程作者在不同环境取值，20 更宽松（橙红也能中）、40 更严格（只认正红）。阈值本来就该按你的实际场景调，不必迷信任何一组"标准值"。

**Q4：能一次 find_blobs 传三组阈值吗？和循环有什么区别？**
A：可以，`img.find_blobs(thresholds)` 会同时匹配三组颜色，速度略快；但返回的 blob 列表混在一起，需要自己判断每个 blob 属于哪组阈值。循环写法慢一点，但 i 直接就是类别编号，代码更好扩展，适合教学。

**Q5：画面里明明只有红色物体，为什么偶尔闪出蓝框？**
A：某些深红/紫红物体的 B 通道值可能落入蓝色阈值区间（本例蓝色 B 为 -128~-20 但 A 为 0~90 较宽）。收紧蓝色阈值的 A 范围（如 0~50），或调大 pixels_threshold 过滤小面积误检。
