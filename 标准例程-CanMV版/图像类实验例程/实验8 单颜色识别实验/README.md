# 实验8 单颜色识别实验

> 用 find_blobs 在画面中找出红色色块并框出来，是颜色识别的入门必修课。难度：**初级**

## 1. 例程简介

本例程调用 `img.find_blobs()`，按 LAB 颜色阈值在摄像头画面中搜索**红色**色块，把每个色块用红色矩形框标出，串口打印帧率。代码中同时预置了红、绿、蓝三组阈值，改一个下标就能切换识别的颜色。学习知识点是 LAB 颜色空间、颜色阈值、find_blobs 与 pixels_threshold。难度为**初级**，预期用途是"找到某个颜色的物体在哪里"，是色块追踪（实验11）、颜色分拣等项目的基础。

## 2. 硬件连接与原理

用到的外设（以 main.py 实际代码为准）：

| 外设 | 代码依据 | 说明 |
| --- | --- | --- |
| MIPI CSI 摄像头 | `Sensor(width=1280, height=960)`，`set_framesize(Sensor.VGA)`，`set_pixformat(Sensor.RGB565)` | 输出 VGA（640x480）RGB565 **彩色**图像 |
| 2.4 寸 MIPI LCD | `Display.init(Display.ST7701, width=640, height=480, fps=90, to_ide=True)` | ST7701 驱动，同步输出 IDE |

原理通俗讲解：颜色识别的核心是"把符合某种颜色的像素挑出来，再把连成一片的像素归为一个色块"。挑像素的标准就是**颜色阈值**——一个范围，落在范围内的像素算"目标颜色"。CanMV 的 find_blobs 在 **LAB 颜色空间**中比较颜色（比 RGB 更接近人眼感受、对光照变化更鲁棒），把所有命中的像素做连通分析，输出一个个 blob（色块）对象。

> [!WARNING]
> 新手风险提醒：摄像头/LCD 排线必须**断电插拔**，插反可能烧毁器件；供电请使用 5V/2A 以上稳定电源。颜色识别对光照敏感，但这是算法问题不是硬件问题，别急着换硬件。

## 3. 相关前置知识

- **像素与 RGB**：RGB 用红绿蓝三个分量描述颜色，但同样的红色在强光/暗光下 RGB 值差别很大，所以颜色识别一般不用 RGB。
- **LAB 颜色空间**：把颜色拆成三个通道——**L** 亮度（0~100）、**A** 红绿轴（负值偏绿，正值偏红）、**B** 黄蓝轴（负值偏蓝，正值偏黄）。LAB 把"亮度"和"色彩"分开，光照变化主要影响 L，颜色判断更稳定。
- **颜色阈值 (l_lo, l_hi, a_lo, a_hi, b_lo, b_hi)**：六个数分别是 L、A、B 通道的最小/最大值。例如红色的 `(0, 80, 40, 80, 10, 80)`：亮度 0~80、A 通道 40~80（偏红）、B 通道 10~80。
- **blob（色块）**：一片连通的目标颜色像素区域，带有位置、面积等属性。
- **pixels_threshold（面积门槛）**：像素数少于该值的 blob 被丢弃，用于过滤小噪点。本例 200，即小于 200 像素的"红点"不算数。
- **blob[0]~blob[3]**：blob 对象支持索引访问，分别是外接矩形的 x、y、w、h。
- **帧率 FPS**：clock 对象统计。

## 4. 软件代码逻辑说明

### 第一步：定义 LAB 颜色阈值

```python
# 颜色识别阈值 (l_lo, l_hi, a_lo, a_hi, b_lo, b_hi) 即LAB模型，对应 LAB 色彩空间中的 L、A 和 B 通道的最小和最大值
thresholds = [(0, 80, 40, 80, 10, 80), # 红色
              (0, 80, -120, -10, 0, 30), # 绿色
              (0, 80, 0, 90, -128, -20)] # 蓝色
```

三组阈值对应红、绿、蓝。想识别绿色把下面代码里的 `thresholds[0]` 改成 `thresholds[1]`，蓝色改成 `thresholds[2]`。

### 第二步：初始化摄像头与显示

```python
sensor = Sensor(width=1280, height=960) # 构建摄像头对象
sensor.reset() # 复位和初始化摄像头
sensor.set_framesize(Sensor.VGA)    # 设置帧大小VGA(640x480)，默认通道0
sensor.set_pixformat(Sensor.RGB565) # 设置输出图像格式，默认通道0

Display.init(Display.ST7701, width=640, height=480, fps=90, to_ide=True)
MediaManager.init() # 初始化media资源管理器
sensor.run() # 启动sensor
clock = time.clock() # 构造clock对象
```

颜色识别必须用 RGB565 彩色格式。

### 第三步：主循环——找色块、画框

```python
while True:
    os.exitpoint() # 检测IDE中断
    clock.tick()  # 记录开始时间（ms）
    img = sensor.snapshot() # 从通道0捕获一张图
    blobs = img.find_blobs([thresholds[0]], pixels_threshold=200) # 0,1,2分别表示红，绿，蓝色。
    for blob in blobs:
        img.draw_rectangle(blob[0], blob[1], blob[2], blob[3], color=(255, 0, 0), thickness=4)

    # 显示图片
    Display.show_image(img)
    print(clock.fps()) # 打印FPS
```

关键函数说明：

- `img.find_blobs([thresholds[0]], pixels_threshold=200)`：
  - 第一参数是**阈值列表**（列表里放几组阈值就能同时找几种颜色，本例只放红色一组）；
  - `pixels_threshold=200`：面积小于 200 像素的色块被忽略，抗噪点；
  - 还可加 `area_threshold`（面积门槛，含空洞）、`roi`（限定区域）、`merge`（合并相近色块）等参数（本例未用）；
  - 返回 blob 列表，找不到时为空列表。
- `blob[0], blob[1], blob[2], blob[3]`：色块外接矩形的 x、y、宽、高，直接传给 `draw_rectangle` 画红框（thickness=4）。
- blob 还有常用方法：`blob.pixels()` 像素数、`blob.cx()/cy()` 质心坐标、`blob.w()/h()` 宽高（本例只用了索引取矩形）。

### 第四步：异常处理与资源释放

`finally` 中依次 `sensor.stop()` → `Display.deinit()` → `MediaManager.deinit()`。

**可调参数**：
- `thresholds[0]`（第 46 行）：换成 [1]/[2] 切换绿/蓝。
- 阈值六元组（第 26~28 行）：**必须按你的实际环境用 IDE 阈值编辑器重新取**（见常见问题 Q1）。
- `pixels_threshold=200`：目标小、离得远时调小（如 50）；噪点多时调大。

## 5. 运行效果

- **屏幕画面**：LCD 和 IDE 显示摄像头彩色画面，画面中的红色物体被红色矩形框（宽 4）套住；移动物体，框实时跟随。
- **串口打印**：每帧打印一次帧率数字，如 `58.7`。
- **成功现象**：拿一个红色物体（红盒子、红色打印色卡）在镜头前，能稳定框住；画面中其他颜色不被框。
- **失败现象排查**：
  - 找不到色块 → 预置 LAB 阈值与你的物体/光照不匹配，用 IDE"工具→机器视觉→阈值编辑器"重新取阈值（最常见原因）；
  - 框住一堆奇怪的地方 → 阈值范围太宽，收紧 A、B 通道范围；调大 pixels_threshold；
  - 框闪烁不稳定 → 光线变化大，固定光源；或把 L 通道范围放宽。

## 6. 代码使用说明

1. 用 **CanMV IDE** 打开本文件夹 `main.py`（IDE 与板载 **CanMV K230D 固件**版本需匹配）。
2. USB 连接开发板，点击 IDE 连接按钮，再点击运行。
3. LCD 与 IDE 同步显示识别结果，串口终端打印帧率。
4. **强烈建议先取阈值**：运行例程后，在 IDE 中选"工具 → 机器视觉 → 阈值编辑器"，选择帧缓冲区作为图像源，拖动滑块只让目标颜色变白，把得到的六元组替换代码第 26~28 行对应项。
5. 本例程**不需要额外文件**、无 SD 卡依赖；脱机自启动将 main.py 放入 TF 卡 `/sdcard/`。

> [!NOTE]
> 阈值没有"万能值"。同一块红色物体，在教室白光、家里暖光、室外阳光下取出的 LAB 阈值都可能不同，换环境后建议重新取一次。

## 7. 拓展思考

1. **一次找三种颜色**：把调用改成 `img.find_blobs(thresholds, pixels_threshold=200)`（传入整个列表），再用不同颜色框区分（需要自己记录每组阈值对应关系），实现多颜色识别（即实验9 的方向）。
2. **输出色块位置**：用 `blob.cx()`、`blob.cy()` 计算色块中心相对画面中心的偏差，通过 UART 发送 `BLOB,x,y,area` 协议，让下位机/小车朝红色物体移动。
3. **按面积筛选最大色块**：遍历 blobs 找 `blob.pixels()` 最大的一个，只画它，实现"锁定最大红色目标"，为色块追踪（实验11）做铺垫。

## 8. 常见问题

**Q1：为什么代码运行后完全找不到我的红色物体？**
A：预置阈值是在作者的灯光环境下取的，你的环境（光源色温、物体材质、曝光）不同，LAB 值就会不同。**必须用 IDE 阈值编辑器对着实际画面重新取阈值**，这是颜色识别实验的第一条铁律。

**Q2：LAB 的 A、B 通道取值范围为什么有负数？**
A：CanMV 中 L 为 0~100，A、B 为 -128~127。A 负值偏绿、正值偏红；B 负值偏蓝、正值偏黄。所以绿色阈值 A 是 (-120, -10)，蓝色阈值 B 是 (-128, -20)。

**Q3：pixels_threshold 和 area_threshold 有什么区别？**
A：pixels_threshold 比较的是色块**实际命中像素数**；area_threshold 比较的是**外接矩形面积**（含色块内部空洞）。过滤噪点常用 pixels_threshold 即可，本例只用了它。

**Q4：为什么框会突然变大，把两个分开的红色物体框成一个？**
A：两个色块靠得很近时 find_blobs 可能把它们连同中间的命中像素视为一个连通区域。可以拉开距离，或给 find_blobs 传 `merge=False`（默认不合并）并调大 pixels_threshold；也可在应用层按 blob 面积拆分处理。

**Q5：识别距离远一点就找不到了？**
A：物体越远像素越少，低于 pixels_threshold=200 就被过滤了。远距离应用把 pixels_threshold 调小（如 50），同时注意太小会引入噪点误检。

**Q6：打印 `clock.fps()` 有什么用？可以去掉吗？**
A：帧率是衡量算法实时性的指标，find_blobs 在 VGA 下一般能跑几十 FPS。调试完可以注释掉减少刷屏，不影响功能。
