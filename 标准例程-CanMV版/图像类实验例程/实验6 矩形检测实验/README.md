# 实验6 矩形检测实验

> 找出画面中的矩形物体，画出外框和四个角点，可用于识别卡片、盒子、纸张。难度：**初级**

## 1. 例程简介

本例程调用 `img.find_rects()` 检测画面中的矩形，用红色矩形框标出，并在四个角上画绿色小圆点，串口打印矩形信息和帧率。学习知识点是 find_rects 的 threshold 参数、`r.rect()` 外接矩形与 `r.corners()` 旋转角点的区别。难度为**初级**，预期用途是检测银行卡、书本、纸盒、二维码白色底板等矩形目标，也可作为"是否对准了某个矩形区域"的判断依据。

## 2. 硬件连接与原理

用到的外设（以 main.py 实际代码为准）：

| 外设 | 代码依据 | 说明 |
| --- | --- | --- |
| MIPI CSI 摄像头 | `Sensor(width=1280, height=960)`，`set_framesize(Sensor.QVGA)`，`set_pixformat(Sensor.RGB565)` | 传感器按 1280x960 构建，通道0 输出 **QVGA（320x240）** RGB565 图像 |
| 2.4 寸 MIPI LCD | `Display.init(Display.ST7701, width=640, height=480, to_ide=True)` | ST7701 驱动，640x480 缓冲，小图居中显示，同步输出 IDE |

原理通俗讲解：矩形检测内部综合了直线/线段信息——先找出图像中的强边缘线段，再寻找"能围成一个四边形"的线段组合，要求对边平行、角接近直角。`find_rects` 对**有清晰直线边缘、对比度强**的矩形（如白纸放在深色桌面上）效果最好；对圆角、模糊、被遮挡的矩形容易漏检。

> [!WARNING]
> 新手风险提醒：摄像头/LCD 排线必须**断电插拔**，插反上电可能烧毁器件；请使用稳定的 5V/2A 以上电源，供电不足可能导致摄像头初始化失败。

## 3. 相关前置知识

- **边缘与线段**：矩形是由四条线段围成的形状，检测前先提取边缘（概念见实验2、实验4）。
- **threshold（累加器阈值）**：本例 `threshold=8000`，表示"构成这个矩形的边缘强度总和"必须超过 8000 才被接受。越大越严格（只认边缘非常强的矩形），越小越宽松（易误检）。矩形检测计算量大，通常配 QVGA 小图使用。
- **外接矩形 rect()**：`r.rect()` 返回 (x, y, w, h)，是**不带旋转**的水平外接框，用于 `draw_rectangle`。
- **旋转角点 corners()**：`r.corners()` 返回矩形的 4 个实际角点坐标列表 [(x1,y1), (x2,y2), (x3,y3), (x4,y4)]，能反映矩形在画面中的**倾斜姿态**。
- **r.w() / r.h() / r.magnitude()**：矩形宽、高、检测强度（可信度），magnitude 越大越可信。
- **居中显示偏移**：`x=round((640 - sensor.width()) / 2)` 让 320x240 画面显示在 640x480 屏幕正中。
- **帧率 FPS**：`clock.tick()/fps()` 统计。

## 4. 软件代码逻辑说明

### 第一步：初始化摄像头与显示

```python
sensor = Sensor(width=1280, height=960) # 构建摄像头对象
sensor.reset() # 复位和初始化摄像头
sensor.set_framesize(Sensor.QVGA)   # 设置帧大小QVGA(320x240)，默认通道0
sensor.set_pixformat(Sensor.RGB565) # 设置输出图像格式，默认通道0

Display.init(Display.ST7701, width=640, height=480, to_ide=True)
MediaManager.init() # 初始化media资源管理器
sensor.run()        # 启动sensor
clock = time.clock() # 构造clock对象
```

### 第二步：主循环——找矩形、画框、画角点

```python
while True:
    os.exitpoint() # 检测IDE中断
    clock.tick()   # 记录开始时间（ms）
    img = sensor.snapshot() # 从通道0捕获一张图
    for r in img.find_rects(threshold=8000):
        img.draw_rectangle([v for v in r.rect()], color=(255, 0, 0))
        for p in r.corners(): img.draw_circle(p[0], p[1], 5, color=(0, 255, 0))
        print(r)
    # 显示图片
    Display.show_image(img, x=round((640 - sensor.width()) / 2), y=round((480 - sensor.height()) / 2))
    print(clock.fps()) # 打印FPS
```

关键函数说明：

- `img.find_rects(threshold=8000)`：返回 rect 对象列表；也可传 `roi=(x,y,w,h)` 只在感兴趣区域检测（本例未用，加上可明显提速）。
- `[v for v in r.rect()]`：把 (x, y, w, h) 元组转成列表，传给 `draw_rectangle` 画红色外框。
- `for p in r.corners(): img.draw_circle(p[0], p[1], 5, color=(0,255,0))`：遍历 4 个角点，每个角点画一个半径 5 的绿色圆点——这样你能看出矩形的真实倾斜角度，而不只是水平外框。
- `print(r)`：打印矩形对象（含位置、大小、magnitude）。

### 第三步：异常处理与资源释放

`finally` 中依次 `sensor.stop()` → `Display.deinit()` → `MediaManager.deinit()`，保证 IDE 停止运行后资源被正确释放，避免下次运行报资源占用错误。

> [!NOTE]
> find_rects 是本章实验里计算量最大的算法之一，第一次运行看到帧率明显偏低不要慌，这是算法特性而不是板子故障；把它当作"低频检测"（每秒确认几次即可）来设计应用会更合理。

**可调参数**：
- `threshold=8000`（第 40 行）：检不到矩形先降到 4000~6000；误检（把杂乱背景框成矩形）时升到 10000 以上。
- `set_framesize`：QVGA 是速度与效果的折中，改 VGA 精度提高但帧率大幅下降（find_rects 本身较慢）。
- 可给 `find_rects` 加 `roi` 缩小搜索范围。

## 5. 运行效果

- **屏幕画面**：屏幕中央 320x240 摄像头画面中，检出的矩形被红色外框套住，四个角上有绿色圆点；把一张 A4 纸或一本书放在深色桌面上，能看到清晰的框和角点。
- **串口打印**：每检出一个矩形打印一次对象信息，每帧打印一次帧率（find_rects 计算量大，帧率会明显低于其他实验，属正常）。
- **成功现象**：红框贴合矩形物体，轻微转动纸张时四个绿点跟着转。
- **失败现象排查**：
  - 找不到矩形 → 目标边缘对比度不够（白纸+白桌），换深色背景；threshold 调小；
  - 误检一堆框 → threshold 调大；避开有直线纹理的背景（地板砖、键盘）；
  - 帧率个位数 → 正常现象，可加 roi 或维持 QVGA。

## 7. 拓展思考

1. **文档扫描仪雏形**：取 `r.corners()` 的 4 个角点坐标通过 UART 输出，上位机据此做透视矫正裁剪，理解"角点比外接框更有用"的场景。
2. **矩形大小分级**：用 `r.w()*r.h()` 计算面积，面积大于某阈值时串口输出"BIG"否则"SMALL"，模拟分拣判断。
3. **结合颜色**：先用实验8 的 `find_blobs` 找到红色区域，再对色块的外接框附近调用 `find_rects(roi=...)`，验证"红色矩形卡片"是否存在，练习多算法组合。

## 8. 常见问题

**Q1：红框是水平的，但我的纸是斜的，为什么框不跟着斜？**
A：`draw_rectangle` 画的是 `r.rect()` 水平外接框，不表示旋转。真实倾斜姿态看四个绿色角点（`r.corners()`），也可以自己用 `draw_line` 把相邻角点连成四边形。

**Q2：find_rects 帧率很低（几 FPS），是板子性能不行吗？**
A：不是。矩形检测需要在所有线段组合中搜索四边形，本身就是重量级算法，QVGA 下几 FPS 到十几 FPS 属正常。加 roi 缩小范围是最有效的提速手段。

**Q3：threshold=8000 该怎么理解？调到多少合适？**
A：它是矩形边缘强度的累计门槛，与分辨率、光照、目标对比度相关。建议从 8000 起步：漏检降 2000 试一次，误检升 2000 试一次，逐步逼近你的场景最佳值。

**Q4：为什么检测到的是二维码的"白底"而不是二维码图案？**
A：find_rects 找的是"强直线边缘围成的四边形"，二维码内部的点阵不构成直线边缘，而其白色底板与深色桌面形成的大矩形轮廓最明显。要识别二维码内容请用实验13。

**Q5：能不能同时检测多个矩形？**
A：可以，`find_rects` 返回列表，for 循环会把画面中所有超过阈值的矩形都画出来；互相嵌套的矩形可能都被检出，属正常现象。

**Q6：如何判断检出的是"近似正方形"还是"长条形"？**
A：用 `r.w()` 和 `r.h()` 计算长宽比：`ratio = r.w() / r.h()`，比值接近 1（如 0.8~1.2）是正方形，远大于或远小于 1 是长条形。结合面积 `r.w()*r.h()` 还能进一步过滤小物体。

**Q7：绿点画在红框外面，是不是检错了？**
A：不是。红框是水平外接矩形，绿点是矩形真实的 4 个旋转角点；当物体倾斜时角点自然落在水平外框附近甚至框线上，两者共同描述了"带姿态的矩形"。物体摆正后绿点会与红框四角重合。
